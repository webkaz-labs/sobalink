# sobalink の実装と残る受入条件

[概要](../README.md) · [使い方](GENERIC.ja.md) · [確認範囲](VERIFICATION.md) · [開発方針](DEVELOPMENT_PRINCIPLES.ja.md)

端末同士をつなぎ、必要なアプリのサービスを使うことを中心に、ローカル画面と CLI を整えています。文字・画像・ファイル・フォルダー転送も利用できます。次の配布候補は `0.3.0-alpha.1` ですが、未公開です。実装済みと実機受入済みを区別します。[固定行ごとの機能対応と受入](FEATURE_PARITY.ja.md)で、旧版の復元・新規拡張・未完了の操作経路を確認できます。

## 実装と残る確認

| 項目 | 実装済みの範囲 | 残る受入 |
| --- | --- | --- |
| 端末とサービス | Tailnet／明示した Tailcat、現在の相手、同番号 TCP 範囲、単一ポート対応、UDP、プリセット | 実認証、2台の実アプリ、TLS・ホスト鍵、direct LAN/WAN/NAT |
| 有効期間と容量 | 共有は有限1時間の既定または明示した解除まで、接続は停止まで。論理の既定・有限・無制限と、調整可能な有限予算 | 最終ソースの全経路で大きい設定・容量不足・復旧・負荷を確認 |
| 保存した操作 | オフラインの停止定義、プロフィール入出力、グループ、部分開始のロールバック、所有リース付きローカルタスク、共有一括停止 | 実導入環境で繰返し・取消・終了・競合の操作 |
| 認証と起動 | 公式ブラウザー・非公開リンク・ローカル QR、待機／取消／承認待ち、背景起動、確認付きユーザー起動登録、外向き限定の任意起動許可、Tailnet ログアウト | 実認証・スマートフォン読取り・OS サインイン／スリープ復帰 |
| 任意プロキシ・診断 | 認証付き SOCKS5 TCP CONNECT、現在の相手・許可ポート、実行時入力または明示した非公開保存・生成、明示的な1回の TCP 検査、実行中の直近失敗 | ネイティブソケット、実アプリ、最終画面の受入 |
| 文字・一括転送 | 明示送信、個別承認、相手限定自動保存、非上書き、一時保存の期限選択、確認付き履歴整理 | 実ファイルと OS 別保存、容量・中断・再試行、空フォルダー |
| ローカル画面 | 接続を中心とする画面、日英、容量・保存操作、接続図、秘密を限定した認証案内 | 新 Playwright Test の実行・画像、実フォント・ネイティブ IME・狭い表示 |
| 配布 | 手動の exact-main CI ゲート、4対象パッケージ、反復ビルド、署名・provenance・実導入検査の準備 | 最終ソース CI の全合格、署名付き公開、公開取得と4対象 mise 実導入 |

公開基準 `1027f04a` の [run 37095653635](https://github.com/webkaz-labs/sobalink/actions/runs/37095653635) は正式な Playwright 23ケース中20合格・3失敗です。race/vet・中継 fixture・パッケージを含む4対象のジョブとマニフェストは合格しましたが、ブラウザー失敗のため run 全体は不合格です。後続ローカル画面 `1c977c9` の274 DOM 試験や28ケースの列挙、過去の別ソースの成功を、最終ソースの受入として数えません。正確な区分は[検証記録](VERIFICATION.md)にあります。

## 受入の順序

1. 統合した正確なソースの Go race/vet、画面試験、静的型、依存関係と埋込み資材の再生成を通す
2. 4対象のネイティブ CI と本番 Go 本体を使う新しいブラウザー試験を実行し、画像を確認する
3. 2台の現在の識別情報と認証を確認し、TCP/UDP サービス・停止・解除・有限／期限なし・アプリ動作を試す
4. 保存・グループ・タスク・プロキシ・診断・容量の操作を、取消や競合・中断・復旧を含めて確認する
5. 文字・ファイル・自動保存・履歴整理を、受信承認と実際の保存結果まで確認する
6. 合格済みの loopback 中継 fixture を維持し、実 LAN/WAN・経路変化・スリープ・OS 起動を別に検証する
7. 公開時に版とソースを確定し、署名・provenance・公開取得・4対象の実導入を確認する

## 変わらない境界

ネットワークは明示選択し、障害時に自動交換しません。外向きサービス接続は選んだ userspace backend に限定します。共有は現在の相手・範囲・有効期間を確認し、広い TCP 範囲は後から起動するアプリにも有効であることを示します。管理・探索・ピア・ペアリング・プロキシ・バックエンド内部の入口は一般サービスとして共有しません。

32相手・64待受・256項目・1 GiB・600秒は該当する初期設定で、固定の製品最大値ではありません。論理制限をなくしても有限の資源予算、通信形式、本人確認、パス安全性は残ります。保存済み記録は設定縮小で消さず、履歴は確認後に削除します。[容量の契約](CAPACITY.ja.md)

ファイルは自動で開かず、実行せず、上書きしません。自動保存は正確なバックエンド・相手・信頼世代・保存先だけです。相手の一時停止は文字とファイルを遮断し、取消した送信には選び直しが必要です。サービスは別の許可です。再試行は同じ起動中の未完了ファイル全体で、途中バイトや再起動後の再開はありません。

Tailcat は自己ホストまたは明示して信頼した中継先を使い、任意の公開中継へ代替しません。選んだ中継への暗号化ペイロード・HTTPS/ICMP 診断と相手への直接通信を許します。外部通信ゼロ、既存 TCP の維持、実アプリの正常性、遠隔ジョブ完了を通信準備だけで保証しません。

## 別の段階で扱うもの

一括の遠隔管理や、より広いリソース管理の基盤は別のマイルストーンです。現在は遠隔管理 API、遠隔ファイル一覧、ブロードキャスト送信、永続的なオフライン送信箱を実装していません。ローカルタスクやサービス接続から、それらが使えると推測しないでください。

旧 CLI／設定の完全な互換維持は、新しい製品の要件ではありません。機能の復元、実装の検証、リポジトリの更新、署名付き公開はそれぞれ別の段階です。
