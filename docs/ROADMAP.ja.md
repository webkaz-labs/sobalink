# 実装と残る受入条件

[English](ROADMAP.en.md) · [概要](../README.md) · [確認範囲](VERIFICATION.md) · [開発方針](DEVELOPMENT_PRINCIPLES.ja.md)

公開基準は [0.3.0-alpha.5](https://github.com/webkaz-labs/sobalink/releases/tag/v0.3.0-alpha.5)、ソースは `0b14fcfb3e49a7ad6c99bed8e4c67a5e577878d6` です。LAN送信先制限、選んだホストの中継運用、中継なしLAN、高度な任意WAN探索、接続方式の併用、調整可能な中継資源予算を含みます。同一ソースのnative／browser CIと署名付き公開の全15ゲートが合格しました。[検証記録](VERIFICATION.md)を参照してください。実装・自動試験と配布の受入・実端末の受入を区別し、実端末の受入は未完了です。

## 受入の順序

```mermaid
flowchart LR
    S[最終ソースと安全性の確認] --> I[2プロセスと実ソケット]
    I --> N[4ネイティブ対象と実ブラウザー]
    N --> D[署名付き公開とmise導入]
    D --> P[実端末の受入]
```

自動試験の必須条件を満たした後、実端末試験のために明示したプレリリースを公開できます。その前に、外部中継不通での準備済み LAN 起動、認証・許可・非公開情報、サービス入口維持の証明が必要です。未実施の実機試験は未実施のまま記録し、模擬・loopback 成功で合格に変えません。

## 維持する境界と後の課題

初期の方式選択と方式間の相手の関連付けは明示操作です。自動選択は、設定・認証・許可済みの経路から、新しい接続について明確な利用不能を確認した場合に限ります。認可・pin・不明状態・未分類の失敗を別経路で迂回しません。外向きアプリ通信は選択した userspace stack に限定します。経路復旧でサービス期限を延長し、相手・ポートを広げ、取消済み信頼を戻し、取消したファイルを再開しません。ファイルは同じ起動中の項目全体の再試行だけで、途中バイト・再起動後の再開は追加しません。既存 TCP の維持、任意取引の再実行、遠隔ジョブ完了は保証しません。

direct を有効にした通常の単一実行ファイルを維持します。`local` は中継の区分で、直接通信が公開経路を使う場合もあります。任意のLAN制限は指定した宛先を許可する機能で、物理NIC・VPNの固定やプロセス・端末全体の外部通信ゼロを保証しません。管理者権限・OS経路／FW・LANルーター変更を必要条件にしません。広いリソース管理、遠隔管理 API、遠隔ファイル一覧、ブロードキャスト、同期、永続的オフライン送信箱は別の作業です。

CI最適化は別の公開後作業で、alpha.5には含みません。未統合の最適化変更は、公開前に独自のレビューとCIを必要とします。

### 今回の公開後に取り組む操作改善

LAN外の推奨方式はTailscaleです。外部中継の構築・配置と専用の公開中継デーモンは当面の対象外にします。既存の任意WAN候補設定は、到達可能な互換中継と固定pinを既に用意している場合の高度な機能として残します。公開中継の配備手順を製品が提供している意味ではありません。次の中継設定改善はLAN内のホストを対象にします。

次の10項目を、今回の統合版の後のパッチで取り組む内容として採用します。それぞれCLI／Web、日英、許可と失敗時の受入を確認します。

1. 認証付きの初回ペア設定・宛先交換を簡単にする。既存の受信者指定招待QRを土台にし、自動探索とは区別する
2. 安定した相手鍵によるLAN端点追従と許可済み経路の自動選択。現在の固定端点・新規接続の切替だけでは端点移行を提供していない
3. LAN中継の配置・運用を簡単にする。ホストを選ぶ設定は実装済みで、安全なホスト自動選出は実現性を確認する課題として残る
4. 接続失敗の原因と対処が分かる診断・復旧案内
5. 公開されたサービスの一覧・選択・起動。既存の一覧と明示した利用許可を土台にする
6. お気に入りと複数サービスの一括開始・停止。現在のプリセットを発展させ、許可を広げない
7. オフライン設定の保持と許可済み相手の復帰時の再接続。永続的なファイル送信箱とは区別する
8. ローカルポート競合時の代替候補提示。明示した固定ポートの選択を維持する
9. ローカルサービス共有の案内と再利用できる許可プリセット。適用される範囲を確認する
10. 簡潔で対処が分かる状態表示と必要時の詳細。実際の経路と切り替えられない理由を示す

LAN中継ホストの自動選出は未解決の要望として残します。操作改善によって遠隔配置・新しいホスト権限・許可範囲の拡大を暗黙に追加しません。

例と公開証拠は汎用的な内容にします。詳細な確認表はここに重複させず、正式な境界は[容量](CAPACITY.ja.md)・[安全性](SECURITY.ja.md)・[経路の契約](ROUTE_RECOVERY_DESIGN.ja.md)を参照してください。

## CIの待ち時間と条件付き実時間試験

短い安全性・ロジック・4対象・browser確認を毎回維持し、自然な鍵更新とleaseの実時間試験だけを変更範囲に応じて選択します。通信・認証・timer・Core・設定・依存・helper・workflowや不明な変更はfull、正確なfull基準からのdocs／CSSだけの累積変更は省略対象です。releaseは全試験を維持します。[判定・来歴・required check・計測の契約](CI_EFFICIENCY.ja.md)を参照してください。条件付き経路とfull経路のnative CI受入、必須集約checkの保護設定を完了条件にします。
