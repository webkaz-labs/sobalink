# sobalink の実装と残る受入条件

[概要](../README.md) · [使い方](GENERIC.ja.md) · [確認範囲](VERIFICATION.md) · [開発方針](DEVELOPMENT_PRINCIPLES.ja.md)

Go に埋め込んだ React 画面と CLI、Tailnet、一括転送、範囲共有に、Tailcat LAN のアダプターと共通処理・CLI を追加しています。LAN の専用画面、ローカル SVG 接続図、確認・offline 切替復旧をローカルへ統合しました。リポジトリとモジュールは `github.com/webkaz-labs/sobalink` になり、公開版の番号とリリース準備は未完了です。

## 実装と検証を分ける

| 項目 | ソースの範囲 | 残る確認 |
| --- | --- | --- |
| ローカル画面と CLI | `14ee61f8` で4対象ネイティブと従来 Chromium を確認。新画面117試験・厳密な TS・同一バイト2回ビルドも合格 | 新 LAN 画面・実フォント・図の正確なソースのブラウザー CI、実 IME・OS の受入 |
| Tailnet | 独立ノード、公式認証、現在の相手識別 | 実認証、ACL、2台での操作 |
| 一括転送 | 明示送信、一括承認、限定した自動保存、非上書き | 実ファイル、中断、容量、再試行、OS 別の保存先 |
| サービス共有 | 同番号 TCP 範囲、明示相手、除外、最大24時間、UDP 上限 | 実アプリ、期限・解除、ポート競合、負荷 |
| 配布 | soba のパッケージ、埋込み資材、出所・SBOM・ライセンス | 確定ソースの CI、反復ビルド、署名、公開物と実導入 |
| Tailcat | アダプター・Core/CLI に加え、4対象で stock loopback DERP、2分リースをまたぐ130秒 TCP・UDP・解除が合格 | 新しい実 Core 文字・ファイル・共有・解除の CI、実端末・direct LAN/WAN の確認 |

[基準 CI の全6ジョブ](https://github.com/webkaz-labs/sobalink/actions/runs/37042721076)は合格済みですが、その後の変更に流用しません。ローカルのソケット制約と実ネイティブ CI を区別し、単体試験を実通信の合格にしません。経路は不明のままで、図に全員同士の線や速度を作りません。

## 受入の順序

1. 正確なソースの Go race/vet、画面試験、依存関係と資材の再生成を通す
2. 4対象のネイティブ CI と Go 本体を使うブラウザー受入を実行し、画像を確認する
3. Tailnet の2台で認証・信頼・文字・一括転送・停止を確認する
4. 狭い TCP/UDP サービスで期限・解除・予約入口・不許可相手・実アプリを確認する
5. 合格した loopback 中継試験を維持し、実端末・direct LAN/WAN で明示中継先のペアリング・直接／中継・再接続を確認する
6. 許可された公開時に、新しい版の署名・provenance・公開取得・4対象の実導入を確認する

## 固定する境界

ネットワークは明示選択し、障害時に自動交換しません。共有は最大32の明示した相手と24時間以内です。広い範囲は後から起動するアプリにも有効なので、その意味を確認画面に残します。予約された管理・探索・ピア・ペアリング・バックエンド入口は共有しません。

ファイルは自動で開かず、実行せず、上書きしません。自動保存は特定のバックエンド・相手・信頼の世代・保存先に限定します。相手の一時停止は文字とファイルを遮断し、取消した送信はファイルを選び直します。サービス許可は別です。再試行は起動中の未完了ファイル全体で、途中バイトや再起動後の再開を約束しません。

Tailcat は自己ホストまたは明示して信頼した中継先を使い、任意の公開中継へ代替しません。選んだ先への暗号化ペイロード・HTTPS/ICMP 診断と相手への直接通信を許すため、外部通信ゼロとは主張しません。既存 TCP の維持、実アプリの健康状態、遠隔ジョブ完了は別の確認です。

旧 CLI／設定の互換維持は新しい製品の要件に含めません。リポジトリ名の変更は完了しましたが、マージ、新しいリリース、署名付き公開はそれぞれ別の操作です。
