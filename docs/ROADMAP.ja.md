# 実装と残る受入条件

[English](ROADMAP.en.md) · [概要](../README.md) · [確認範囲](VERIFICATION.md) · [開発方針](DEVELOPMENT_PRINCIPLES.ja.md)

公開済みの基準は [0.3.0-alpha.2](https://github.com/webkaz-labs/sobalink/releases/tag/v0.3.0-alpha.2) で、署名付き公開取得と4ネイティブ対象の実導入を確認しています。後続ソースは同じペア端末へ戻る準備済み経路の復旧を追加します。まだ未公開で、ここでは版番号を決めません。実装、自動統合試験、実端末の受入は別の段階です。

[PR #8](https://github.com/webkaz-labs/sobalink/pull/8) では、初回の中継間復旧時間切れの後、修正したネイティブ transport 試作が成功しました。後続のアプリ統合へ結果を引き継ぐことはできません。[検証記録](VERIFICATION.md#経路復旧の条件)で正確なソースと実行結果を管理します。

## 受入の順序

```mermaid
flowchart LR
    S[最終ソースと安全性の確認] --> I[2プロセスと実ソケット]
    I --> N[4ネイティブ対象と実ブラウザー]
    N --> D[署名付き公開とmise導入]
    D --> P[実端末の受入]
```

自動試験の必須条件を満たした後、実端末試験のために明示したプレリリースを公開できます。その前に、外部中継不通での準備済み LAN 起動、認証・許可・非公開情報、サービス入口維持の証明が必要です。未実施の実機試験は未実施のまま記録し、模擬・loopback 成功で合格に変えません。

## 維持する境界と後の課題

バックエンドは明示して切り替え、外向きアプリ通信は選択した userspace stack に限定します。経路復旧でサービス期限を延長し、相手・ポートを広げ、取消済み信頼を戻し、取消したファイルを再開しません。ファイルは同じ起動中の項目全体の再試行だけで、途中バイト・再起動後の再開は追加しません。既存 TCP の維持、任意取引の再実行、遠隔ジョブ完了は保証しません。

direct を有効にした通常の単一実行ファイルを維持します。`local` は中継の区分で、直接通信が公開経路を使う場合もあります。厳密な LAN 限定・外部通信ゼロは未実装で、このソースで解決済みとは扱いません。広いリソース管理、遠隔管理 API、遠隔ファイル一覧、ブロードキャスト、同期、永続的オフライン送信箱は別の作業です。

例と公開証拠は汎用的な内容にします。詳細な確認表はここに重複させず、正式な境界は[容量](CAPACITY.ja.md)・[安全性](SECURITY.ja.md)・[経路の契約](ROUTE_RECOVERY_DESIGN.ja.md)を参照してください。
