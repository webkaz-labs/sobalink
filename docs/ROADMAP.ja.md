# 実装と残る受入条件

[English](ROADMAP.en.md) · [概要](../README.md) · [確認範囲](VERIFICATION.md) · [開発方針](DEVELOPMENT_PRINCIPLES.ja.md)

公開基準は [0.4.0-alpha.4](https://github.com/webkaz-labs/sobalink/releases/tag/v0.4.0-alpha.4)、ソースは `e4f7f4ef0a38a032eef9776c5e4a5d0ea8cbf28f` です。[ファイルの永続送信待ち](DURABLE_OUTBOX.ja.md)はこの公開基準に含まれます。[テキストの永続送信待ち](DURABLE_TEXT.ja.md)は現在の開発ソースに実装していますが未公開です。後者は profile 形式 3 を使い、旧形式との互換・移行・消去は行いません。新しいソースの native／browser／配布にはそれぞれの実行結果が必要です。[検証記録](VERIFICATION.md)の過去の合格を自動で引き継がず、実端末の受入も別に扱います。

## 受入の順序

```mermaid
flowchart LR
    S[最終ソースと安全性の確認] --> I[2プロセスと実ソケット]
    I --> N[4ネイティブ対象と実ブラウザー]
    N --> D[署名付き公開とmise導入]
    D --> P[実端末の受入]
```

自動試験の必須条件を満たした後、実端末試験のために明示したプレリリースを公開できます。その前に、外部中継不通での準備済み LAN 起動、認証・許可・非公開情報、サービス入口維持の証明が必要です。未実施の実機試験は未実施のまま記録し、模擬・loopback 成功で合格に変えません。

## 維持する境界と後の課題

初期の方式選択と方式間の相手の関連付けは明示操作です。自動選択は、設定・認証・許可済みの経路から、新しい接続について明確な利用不能を確認した場合に限ります。認可・pin・不明状態・未分類の失敗を別経路で迂回しません。外向きアプリ通信は選択した userspace stack に限定します。経路復旧でサービス期限を延長し、相手・ポートを広げ、取消済み信頼を戻し、取消したファイルを再開しません。即時ファイル送信は同じ起動中の項目全体の再試行です。明示的なファイル送信待ちは元の ID と期限で再起動後も復旧します。未公開のテキスト送信待ちも独立した保存・重複防止の契約を持ちます。いずれも途中バイト再開は追加しません。既存 TCP の維持、任意取引の再実行、遠隔ジョブ完了は保証しません。

direct を有効にした通常の単一実行ファイルを維持します。`local` は中継の区分で、直接通信が公開経路を使う場合もあります。任意のLAN制限は指定した宛先を許可する機能で、物理NIC・VPNの固定やプロセス・端末全体の外部通信ゼロを保証しません。管理者権限・OS経路／FW・LANルーター変更を必要条件にしません。範囲を限定した[遠隔設定管理](RESOURCE_MANAGEMENT.ja.md)、[共有サービス一覧と接続前確認](CATALOG_VIEW_CONTRACT.ja.md)、選んだ複数宛先への[ファイル配送](GENERIC.ja.md)は既存機能です。より広い管理と同期は別の作業です。明示的なファイル送信待ちは既存機能で、テキスト送信待ちは開発ソースに実装しています。

以前の 0.3 系列の CI 最適化計画は過去の記録です。追加の CI 変更には独自のレビューと確認が必要で、送信待ちの実装により既存 native／browser／配布の条件を省略しません。

### 残る機能範囲と過去の計画

[0.3 系列の利便性計画](CONVENIENCE_PLAN.ja.md)は履歴です。当時の未実装項目を現在の残件一覧として扱いません。特に[近くの端末との接続](CONNECTION_SETUP.ja.md)には依頼・受付・接続開始のみの役割があり、受付側の中継を明示して許可します。従来の指紋全文照合ではQR／テキスト交換と、許可済みで到達可能な中継役の選択を維持します。どちらも他ホストへのソフトウェア配置や、一般的な無人の中継選出・運用を提供しません。

次の項目は現在の実装範囲外で、実装する版は未定です。

- 永続的な共有フォルダーと同期、自動クリップボード同期、遠隔ファイル一覧。明示的なファイル・テキスト配送と、継続的なアクセスや同期は別です。
- 接続方式をまたぐ遠隔管理。実装済みの[管理契約](RESOURCE_MANAGEMENT.ja.md)は managed DirectLAN の相手と正確な設定項目に限定し、一般的な遠隔実行ではありません。
- 転送の途中バイトからの再開と、追加の TUI／ネイティブ画面。永続送信待ちの再起動復旧は既存機能で、全体を延期扱いにしません。
- 公開中継の配備と専用の公開中継デーモン。LAN 外では通常 Tailscale を推奨します。任意の WAN 設定には到達可能な互換中継と固定 pin が必要です。
- 後述する MCP とエージェントからのツール実行。構成と受入は今回の接続・送信待ちとは別の作業です。

実端末の探索、ネットワーク移動、休止復帰、電源断の受入は実装済み動作の検証課題で、対応機能を取り下げたことを意味しません。profile 形式の非互換と移行なしは現在の明示的な境界であり、将来の移行実装を約束するものではありません。

例と公開証拠は汎用的な内容にします。正式な境界は[容量](CAPACITY.ja.md)・[安全性](SECURITY.ja.md)・[経路の契約](ROUTE_RECOVERY_DESIGN.ja.md)を参照してください。

## CIの待ち時間と条件付き実時間試験

短い安全性・ロジック・4対象・browser確認を毎回維持し、自然な鍵更新とleaseの実時間試験だけを変更範囲に応じて選択します。通信・認証・timer・Core・設定・依存・helper・workflowや不明な変更はfull、正確なfull基準からのdocs／CSSだけの累積変更は省略対象です。releaseは全試験を維持します。[判定・来歴・required check・計測の契約](CI_EFFICIENCY.ja.md)を参照してください。条件付き経路とfull経路のnative CI受入、必須集約checkの保護設定を完了条件にします。

## 後の方向性：許可したエージェントに必要なツールを共有する

現在の製品は、範囲を限定したTCP／UDP接続、明示的な共有許可、ローカルCLI／APIを提供します。MCPサーバーや、エージェントからツール実行までをつなぐ機能はまだありません。将来は、共有する側が選んだ遠隔ツールだけを、許可した相手のAIが使えるよう、簡単な共有・確認の手順を検討します。接続相手の本人確認、通信の許可、アプリでの実行権限は分けて扱います。

端末間の接続自体はTailscaleでも実現でき、LAN外の通常の接続先として引き続き利用します。通常のTailscaleと既存アプリだけで目的を満たせるなら、そのまま使う方が簡単な場合があり、sobalinkは必須ではありません。目指す価値は接続だけでなく、管理者権限・ルーターのポート転送設定を前提にしない動作と、簡単なサービス共有、正確な相手・範囲・有効期間の確認の組合せです。ネットワークの到達性と各ツール自身の認証は必要です。実装済みと案内する前に、小さく動くツール共有の実証と安全性レビューを行います。この方向性を、現在の接続セットアップと永続送信待ちの範囲へ追加しません。
