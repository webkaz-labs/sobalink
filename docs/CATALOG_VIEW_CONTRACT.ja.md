# 共有サービス一覧の閲覧契約

[English](CATALOG_VIEW_CONTRACT.en.md) · [開発原則](DEVELOPMENT_PRINCIPLES.ja.md)

最初の実装は閲覧許可の適格性データと、発見情報を公開した元の transport origin
の保持です。承認コマンド、閲覧許可の保存、catalog 行の current 化、接続権限は
まだ追加しません。リリース版番号は未定です。

## 明示選択と既存許可との共存

`resourcegrant.CatalogViewEnvelope` は既存の検査・管理用 `Envelope` から独立し、
それぞれのデコーダーは相互のデータを拒否します。既存の許可レコード、世代、
時刻、active 最大1個の制約、実行時 fence は変更しません。閲覧用には独立した
世代・時刻と active 最大1個の契約を用意します。承認・取消・保存の接続は後続
実装であり、既存許可の自動移行・置換・拡張を行いません。

閲覧レコードは、1つの managed DirectLAN `Relationship`（提供元鍵、相手鍵、
不変のペア binding）、1つのリソース、重複のない昇順の共有 activation ID
1～16個に限定します。ID は既存の共有開始時に生成され、保存設定の ID とは
異なります。共有を再開した場合は ID が変わり、改めて明示選択が必要です。
ワイルドカード、接続、設定検査、管理操作の許可は表現できません。

`MatchesSelection` は適格性の絞込みであり、別相手・別ペア binding・別 activation
ID・取消・期限切れ・不正な期限を拒否します。通信の admission ではありません。
後続の所有権を確認する coordinator は単調な期限、現行の所有権と関係を保持・
確認し、元の publication origin と現行の閲覧許可の下で最終開示を制御します。
接続には引き続き独立した既存のサービス許可が必要です。

## 元の公開情報の保持

発見情報は、既存の publication permit の下で結果を公開するとき、実際の HTTP
処理の単一 transport origin を保持します。キャッシュ削除・backend 初期化時に
origin も消去します。DirectLAN の catalog は保持した origin を使い、現在の相手
を再取得して過去の提供元情報を作り直しません。origin の欠落・停止・置換は
取得元の拒否になります。複数経路の帰属は未対応です。閲覧許可の admission と
提供元情報との結び付けが完成するまで既存の行は `stale` のままです。取得時刻
の更新だけで古い広告を current にしません。

## 後続の完了条件

1. 明示承認と独立した所有権を確認する保存処理を追加し、承認・取消の前後で
   既存の検査・管理許可を保持する。
2. 明示した DirectLAN 相手の許可一覧を取得する。最終開示とレビュー済みの
   サービスを `service.connect` に渡す前に、提供元・activation ID・接続条件・
   期限・現行許可を再確認する。
3. 日英 Web／CLI のレビュー、空状態、エラー、再取得の導線をそろえる。
4. 取消・期限切れ・再ペア・古い選択の競合を実プロセスとブラウザーで確認し、
   実際のサービス利用と既存機能の回帰を確認する。

現時点のテストはデータ契約と元 origin の拒否条件の確認に限り、実機確認や
一連の導線の完了証拠ではありません。既存のブラウザー sandbox 動作・CI 条件
は変更しません。
