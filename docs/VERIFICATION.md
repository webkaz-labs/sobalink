# sobalink の確認範囲

[English](VERIFICATION.en.md) · [使い方](GENERIC.ja.md) · [配布](DISTRIBUTION.md)

**sobalink は未リリースの開発版です。** LAN・ローカル画面・型付き CLI は実装済みですが、公開済み CI と後続のローカル検証は異なるソースです。次の範囲を混同しません。

## 確認済みのネイティブ版

[PR #2](https://github.com/webkaz-labs/sobalink/pull/2) の公開済みコミット `5dd6b8c99b8e0167924b38411889e3a0092ac4af` は、[run 37046723268 の全6ジョブ](https://github.com/webkaz-labs/sobalink/actions/runs/37046723268)に合格しました。Linux x64/ARM64・macOS ARM64・Windows x64 の4対象で、stock Tailcat と loopback TLS DERP を使い、実際の2分中継リースをまたぐ130秒の既存 TCP、双方向 TCP/UDP、不許可鍵の拒否、稼働中の解除と片付けを確認しました。Core の2ピア間の文字・ファイル・共有・解除、ネイティブパッケージ、その版の Go 本体と Chromium の画面検査、マニフェストも合格です。

これは独立した loopback ピアを使う実際のネイティブ CI プロセスです。実端末、direct LAN/WAN/NAT、スリープ復帰、ネイティブ IME、公開リリースの受入ではありません。その後に追加した画面・CLI・Core へ、この結果を流用しません。

## ネイティブと画面の条件

Linux x64/ARM64・macOS ARM64・Windows x64 の race/vet、IPC とソケットの片付け、配布物の実行、日英表示を維持します。クロスコンパイルはネイティブ実行の代わりになりません。ホスト型 Windows CI の成功と、標準ユーザーでの実認証も別です。

画面は実際の Go プロセスと埋込み資材で検査します。コード入力、有効期限・再利用拒否、セッション切れ、移動・戻る・取消、重複操作、古い状態、エラー、キーボードとフォーカス、日英、明暗、狭い表示を確認し、そのビルドの画像を記録します。サーバー起動失敗はブロッカーで、画面の合格ではありません。

誤った Host/Origin、CSRF 不足、別セッション、過大要求、ピア API からの管理操作を拒否する試験も必要です。コード・認証 URL・capability を URL や通常の状態に漏らさないことを確認します。

## 実際の2台で確認する順序

一般的な例を使い、必要な接続・アカウント権限を得ます。ソース、版、OS、ネットワーク、結果、最初の失敗箇所を記録し、非公開状態は公開しません。

1. 新しい状態でネットワーク未選択を確認し、独立 Tailnet ノードを認証して意図した相手を確認する
2. 受信側で正確な送信者を信頼し、文字の明示送信と手動コピーを確認する
3. 画像、複数ファイル、フォルダーを一括にし、辞退・保存先指定・承認・サイズとハッシュ・空フォルダーを確認する
4. 同名、危険なパスとリンク、未対応項目、容量と並列上限、保存失敗、取消で、上書き・自動起動・実行がないことを確認する
5. 特定の相手と保存先だけに自動保存を設定し、一時停止・無効化・識別情報変更・信頼し直しで古い許可が復活しないことを確認する
6. ファイルを中断して先頭から再試行し、保存確認済みを再保存しないことを確認する。再起動後は新しい一括とし、別名コピーの可能性を示す
7. 狭い TCP 範囲を指定した相手に共有し、除外・予約ポート・未許可相手を検査する。範囲内で後から起動するアプリも期限まで対象になることを確認する
8. UDP とローカル待受の上限、競合、明示した番号対応、停止、期限、解除、片付けを試す
9. 相手側に sobalink がない通常の Tailnet サービスへ接続し、アプリの認証・TLS／ホスト鍵・実操作を確認する
10. 観測できる場合だけ直接・中継経路を記録し、回線中断とスリープ復帰を試す。不明を推測で埋めず、既存 TCP 維持を保証しない

通信準備、探索情報、ローカル一時保存は、アプリ成功や到着完了ではありません。停止してもデータ回収や遠隔ジョブ取消にはなりません。

## Tailcat の条件

明示中継先、相手へ結び付けた別々のサーバー／クライアント鍵、sealed bootstrap の入場許可、成功応答前の秘密状態の atomic 保存、UDP 多重化、永続的な解除を実装しました。操作と復旧エラーは [LAN 手順](LAN.ja.md)にあります。ペアリング、アプリの信頼、自動保存、サービス許可は別です。

Tailscale `v1.104.0` と Tailcat `v0.7.1-0.20260929145319-b4dc28e8aa89` を固定し、必要な識別・解除 API を使います。固定とコンパイル成功だけではネイティブのペアリングを実証しません。

希望制のネイティブ試験は `5dd6b8c99b8e0167924b38411889e3a0092ac4af` の [run 37046723268](https://github.com/webkaz-labs/sobalink/actions/runs/37046723268)で4対象すべて合格しました。stock Tailcat/WireGuard と TLS ピン付き loopback DERP により、不正な招待・不明な鍵、双方向 TCP/UDP、実際の2分リースをまたぐ130秒の既存 TCP と DERP 再認可、稼働中の解除・片付けを確認しました。この試験は UDP underlay を除き、外部中継を使いません。

この試験の合格は、実際の direct UDP、LAN/WAN/NAT の移動、中継先変更、速度、既存 TCP 全般の維持を証明しません。試験用の loopback 限定を、本番の外部通信ゼロの保証にしません。本番では相手への直接通信と、明示した信頼済み中継への暗号化ペイロード・HTTPS/ICMP 診断を許します。

既定の公開中継一覧・DNS bootstrap を使わないこと、必須タグ、別中継 capability と未対応のプロキシ・上書き環境の拒否を確認します。不明な経路は不明のままです。統合した図はこの端末と相手の実観測を使い、相手同士の線や速度を作りません。

アプリの解除は許可と通信を直ちに閉じます。中継の2分リースは別で、許可済みセッションが期限まで、bootstrap の一時許可と重なる場合は初回から約4分まで残ることがあります。アプリの遮断と、その後の中継再入場拒否を別々に確認します。

実機では、2台の明示設定と識別情報、承認したファイル・サービス、一時停止後の取消済みファイルの選び直し、offline 修復、証明書期限、解除の永続化、不確かなペアリング、中断と復旧が残っています。任意の公開中継や方式の自動交換は許可しません。
