## ネイティブとブラウザーの受入

4対象すべての race・vet・パッケージ、IPC・ソケットの片付け、日英表示を維持します。ホスト型 Windows の実行は標準ユーザーでの認証や実導入後の起動を証明しません。

ブラウザーは実際の Go 本体と埋込みの本番資材を使います。ローカルコードと期限・再利用拒否、セッション・CSRF・Origin、非公開 Tailnet 認証と承認待ち、ネットワーク設定と修復、相手の選択、サービス・有効期間・番号対応・容量確認、保存定義・グループ、転送と受信設定、停止・解除を検査します。専用フォームのない任意機能は詳細コマンドの範囲も区別します。

戻る・取消・繰返し操作・古い版・中断・ネットワークエラー・キーボード・フォーカス・日英・明暗・狭い表示を含めます。実フォント・文字幅・接続図・詳細画面を確認し、そのビルドの画像を記録します。模擬端末の QR はスマートフォン読取りの合格ではなく、ブラウザーの composition イベントもネイティブ IME の受入ではありません。

不正な Host/Origin、CSRF 不足、別セッション、過大要求、ピアからの管理操作を拒否する試験が必要です。コード・認証 URL・プロキシ認証情報・capability を通常の状態や配布画像に含めません。大きくした論理値が、別の有限予算内で Core・IPC・Web 要求応答・CLI・ブラウザーを通ることも確認します。

## 実際の2台で確認する順序

一般的な例と必要なアカウント・通信権限を使い、ソース・版・OS・方式・結果・最初の失敗段階を記録します。非公開の識別状態は公開しません。

1. 新規プロフィールでネットワーク未選択を確認し、独立 Tailnet ノードの認証または明示した中継先でのペアリングを行い、現在の相手を確認する
2. SSH/SFTP・Web・別の必要なサービスへ接続する。通常の Tailnet 接続先に sobalink は不要。アプリ認証・TLS・ホスト鍵と実操作を確認する
3. 狭い TCP/UDP 範囲を明示相手に共有する。同番号範囲、単一ポート対応、除外、内部入口、不許可相手、後から起動するアプリ、有限期限・明示した解除までを確認する
4. 外向きの停止まで、待受・通信予算、低くした受付設定、競合、共有一括停止、個別停止、信頼解除、片付けを確認し、番号変更や許可更新が無言で起きないことを確かめる
5. オフラインで停止定義を保存・取込み、グループを確認する。一部失敗のロールバック、ローカルタスクの取消、所有範囲の片付け・リース切れで他の処理を止めないことを試す
6. 正確な送信者を信頼し、文字の明示送信・手動コピーを試す。履歴の確認付き整理、容量不足、相手の受信確認後のローカル保存失敗を確認する
7. 画像・複数ファイル・フォルダーを一括にし、辞退と保存先指定の承認、サイズ・ハッシュ・空フォルダーを確認する
8. 不正パス・リンク・同名、有限予算内の独自／無制限設定、一時保存の取消・期限・保存失敗、非上書き・非自動起動を試す
9. 正確な相手・保存先だけの自動保存を有効にし、一時停止・無効化・識別変更・再信頼で古い許可を復活させないことを確認する
10. ファイルを中断して先頭から再試行し、保存確認済みの扱いを検査する。再起動後は新しい一括とし、別名コピーの可能性を示す。永続的なオフライン送信箱はない
11. 任意の認証付き SOCKS5 で許可・不許可 TCP 接続先、認証情報、内部入口、識別変更、停止を確認する。BIND・UDP・OS 接続／DNS への代替がないことを試す。非公開保存・生成・表示、版の競合、無効化・削除・永続的取消しを別に確認し、通常出力・可搬書出しへ認証情報を含めないことを試す
12. 明示した1回の TCP 診断の前後を確認する。実行中の直近失敗情報を保持し、アプリ正常性は未確認のままにする
13. 観測できる direct/relay、通信中断、スリープ復帰、任意のユーザーサインイン時起動を試す。不明経路は不明とし、アプリ再接続を別に確認する。別に許可した外向き・プロキシの起動、範囲変更の拒否、オフライン抑止、有限期間、明示停止後の非復活を試し、受信共有は停止のままであることを確かめる

通信準備、探索情報、ローカル一時保存はアプリ成功や遠隔保存完了ではありません。通信停止はデータ回収や遠隔ジョブ取消ではありません。

## Tailcat の条件

明示中継先、ペアに結び付けた別々のサーバー・クライアント鍵、sealed bootstrap、成功応答前の秘密状態の atomic 保存、UDP 多重化、永続的解除を実装しています。[LAN の操作と復旧](LAN.ja.md)では、ペアリング・アプリ信頼・自動保存・サービス許可を分けます。ペア受付は選んだ論理設定に従い、秘密状態の保存容量は別の有限予算です。件数を下げても既存ペアは残します。

依存先は Tailscale `v1.104.0`、Tailcat `v0.7.1-0.20260929145319-b4dc28e8aa89` です。記録した alpha.2 のネイティブ fixture は実 stock Tailcat/WireGuard と TLS ピン付き loopback DERP を使います。記録した4対象 CI は、不正招待・不明鍵、双方向 TCP/UDP、実際の2分リースをまたぐ130秒の既存 TCP と再認可、稼働中の解除・片付け、Core の2ピア文字・ファイル・共有を含みます。UDP underlay は除き、外部中継は使いません。

この fixture は実 direct UDP、LAN/WAN/NAT の移動、中継先変更、速度、既存 TCP 全般の維持を証明しません。本番は相手への直接通信、明示した信頼済み中継への暗号化ペイロードと HTTPS/ICMP 診断を許します。loopback 限定の fixture は外部通信ゼロの保証ではありません。

既定の公開中継一覧・DNS bootstrap の不使用、必須タグ、別中継 capability・未対応 proxy/backend 上書きの拒否を確認します。多数の相手への探索は有限数ずつ巡回し、図の線・速度は実際の証拠から作ります。

アプリの解除は許可と追跡中通信を直ちに閉じます。中継の2分リースは別で、許可済みセッションが期限まで、一時許可と重なる場合は初回 bootstrap から約4分まで残る可能性があります。アプリの遮断と後の中継再入場拒否をそれぞれ確認します。

実機では明示設定と識別、承認済みのサービス・ファイル操作、一時停止後の取消済みファイルの選び直し、オフライン修復、証明書期限、不確かなペアリング、永続解除、ネットワーク復旧を確認します。任意の公開中継や方式の自動交換はしません。

製品は direct を有効にした通常の単一バイナリです。UDP を除いた隔離 fixture は狭い証拠であり、通常の直接通信や外向き通信を厳密に限定する製品を検証しません。ネイティブ受入は制御した中継 fixture と実際の製品構成の両方を必要とします。過去の経路復旧だけのソースには厳密な送信先制限はありませんでした。現在の統合では明示した送信先の許可を追加しますが、物理NICの隔離や端末全体の外部通信ゼロではありません。local中継の区分だけでは相手への公開された直接経路を止めません。

明示したプレリリースの前に、統合自動試験、認証・許可・非公開情報のレビュー、最終ソースの native/browser、署名付き実導入を通します。実端末受入は未実施と明示して残し、その試験のために mise 導入を提供できます。既存 TCP の維持、任意要求の再実行、ファイルの途中バイト・再起動後の再開を宣伝しません。待受準備、認証済み経路の証拠、アプリ成功、遠隔ジョブ完了を区別します。

## 公開の条件

[配布](DISTRIBUTION.md)では、公開に選んだ正確な main の CI、実ブラウザー受入、反復ビルド、署名・provenance、独立した公開取得、4ネイティブ対象での実導入を必要とします。[sobalink Releases](https://github.com/webkaz-labs/sobalink/releases) で、選んだ版の資材・ソース・リンクされた workflow の結果を確認してください。準備した workflow、ドラフト PR、条件付きの導入例、候補番号だけでは公開の証拠になりません。

過去の [tsnet-bridge 公開版](https://github.com/webkaz-labs/tsnet-bridge/releases) は当時の実行ファイル・設定・署名情報を保持します。その導入結果や特定アプリの結果を、この製品の証拠にはしません。
