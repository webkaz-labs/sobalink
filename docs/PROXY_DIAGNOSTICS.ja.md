# 任意のプロキシと診断

[English](PROXY_DIAGNOSTICS.en.md) · [汎用ガイド](GENERIC.ja.md) · [セキュリティ](SECURITY.ja.md)

詳細設定の SOCKS5 入口と明示的な TCP 診断を、`soba` と認証済みのローカル操作 API で利用できます。サービス接続と同じ現在の端末 ID と通信ポリシーを使います。新しいロジックはモックとメモリ内通信で確認済みです。実際のソケット、実機、アプリ互換性の検証は別の受入項目です。

## 任意のプロキシを確認する

プロキシは任意の機能です。サービスが 1 個なら、通常の `soba connect` の方が簡単です。

```sh
soba proxy preview --name example-proxy --peer PEER_ID --ports 443,8443
soba proxy preview --name example-proxy --peer PEER_ID --ports 443 --ttl 72h
```

確認結果には正規化した完全な `scope`、その `revision`、接続先の端末名、ループバックの入口が含まれます。名前、ネットワーク、正確な端末 ID と TCP ポート、入口、有効期間を確認してください。この操作では入口を開きません。既定は `until-stopped` です。正の整数秒の `--ttl` で有限の期間を指定でき、24 時間を超える期間にも対応します。どの許可も本体のプロセス終了時に失効します。

返された `scope` を開始用の非公開入力に入れ、`revision` を `expectedRevision` にコピーして、アプリに設定する `username` と `password` を明示してください。認証情報は各 1〜255 バイトです。非公開ファイルかパイプを使い、コマンド引数、共有設定、ログ、ソース管理に含めないでください。CLI は開いたファイルが現在の OS ユーザーだけに許可されていることを確認します（Unix では 0600 相当、Windows では本人だけの保護された ACL）。

```sh
soba proxy start --json-file PRIVATE_INPUT_FILE
soba proxy start --stdin < PRIVATE_INPUT_FILE
soba proxy list
soba proxy stop PROXY_ID
```

複数の相手には `soba proxy preview --json-file SCOPE_FILE` または `--stdin` を使えます。JSON は `scope` を持つオブジェクトです。`targets` は `peerId` と `port` を持つオブジェクトの配列です。論理的な `sharePeers` 設定は異なる端末 ID の個数を数え、接続先のメタデータは有限のローカル操作サイズで制限します。入口と TCP 接続は通常の資源制御と、入口数・接続数・許可別・相手別の容量を共有します。容量を下げた場合は新しい許可や接続に適用します。

ローカル操作 API は `proxy.preview`、`proxy.start`、`proxy.list`、`proxy.stop` です。通常の状態、確認、一覧、開始結果に認証情報は含まれません。CLI の dry-run は未知の追加項目も含め認証情報を出力しません。通常の `proxy start` は認証情報を保存しません。明示した[非公開プロキシ設定](STARTUP.ja.md)は別の保護領域で確認付き保存・生成・非公開ファイルへの表示・任意の次回起動に対応します。可搬プロフィールの書き出しには認証情報・起動許可を含めません。

入口は `127.0.0.1` または `::1` に限定され、ユーザー名とパスワードで認証し、TCP CONNECT だけに対応します。BIND と UDP ASSOCIATE は使えません。接続は選択したユーザー空間の通信基盤と、現在も一致する承認済み端末 ID、正確に許可した TCP ポートを使います。不明な名前を OS の DNS で解決したり、OS の通常接続に切り替えたりしません。管理用ポートは接続先にできません。プロキシの入口はローカルポートの対応付けも含めサービス共有の対象にできず、すでに共有中のポートに入口を作ることもできません。

ネットワーク切断、相手の取消し、端末 ID の変更、期限切れ、ログアウト、入口の障害、本体終了で停止します。一時的なプロキシの再開始には再確認と実行時の認証情報が必要です。別に保存した許可は明示した再開始・元の期限内の復旧・希望した次回の本体起動に使えます。範囲変更・相手の許可取消しには再確認が必要です。停止で管理中の接続は閉じますが、アプリがすでに受け付けた処理を取り消すものではありません。

## 失敗を確認し、TCP 接続先を 1 個調べる

```sh
soba doctor
soba doctor --service SERVICE_ID --tcp
soba doctor --service SERVICE_ID --tcp --port 8443
```

`--tcp` なしでは現在の観測と直近の実行時エラーを表示します。`--tcp` を付けると、開始済みサービスの許可した接続先に接続を 1 回開いて閉じます。範囲指定のサービスでは有効範囲内のポートを 1 個指定してください。転送先の確認は選択したユーザー空間の通信基盤と現在の端末 ID を使います。共有先の確認は、その共有で許可した数値ループバックだけを使い、確認済みのローカルポート対応付けにも従います。

成功時は `tcp_reachable`、通信の状態は `reachable`、アプリは `unverified` を返します。確認できるのは TCP 接続の受付だけです。アプリのデータを送らず、アプリの正常動作、互換性、TLS、ホスト鍵、ログインの成功は確認しません。汎用的な UDP の確認でもこれらを証明できないため、UDP の診断は受け付けません。

結果には共通のコード、UTC の確認時刻、日本語と英語の次の操作が含まれます。ローカルのサービス一覧は、確認や通信復旧に成功した後、または停止後も `lastFailure` を保持します。追加した失敗履歴は本体終了または定義削除で消えます。旧版が表示していたのはその時点の診断結果だけで、いずれも再起動をまたぐ診断記録ではありません。生の接続先エラーやローカルの対象は、相手へのサービス発見情報に含まれません。診断は許可期限を延長せず、保存済み定義を変更しません。

### 接続状態から分かる次の操作

ローカルWebの案内、`soba status`の次の操作、probeなしの`soba doctor`のJSONは、
報告された接続状態を同じ基準で説明します。設定不足、ローカルアドレスの利用可否、
ID／pin確認、証明書、資源容量、保存状態の復旧、原因不明を区別します。
Webから該当する確認画面を開くか、明示的に状態を更新できます。待機中の表示だけで
操作を再試行しません。案内はprobeや許可変更を行わず、実際のdirect／relay経路や
アプリの成功を確定しません。技術的なコードと詳細は必要なときに確認できます。
