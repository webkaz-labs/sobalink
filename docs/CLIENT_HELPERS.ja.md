# アプリの接続設定と RustDesk ヘルパー

[English](CLIENT_HELPERS.en.md) · [利用ガイド](GENERIC.ja.md) · [開発原則](DEVELOPMENT_PRINCIPLES.ja.md)

`soba settings` は保存した接続先、正確なポート対応、現在の待受状態、アプリ別のヒントを表示します。RustDesk ヘルパーは4つの転送設定とサーバーの公開鍵を1つのグループとして保存します。アプリ設定の変更や待受の開始は行いません。自動テストでは保存情報とコマンドの動作を確認していますが、RustDesk の画面表示・操作は未検証です。

## 通常のアプリに接続先を設定する

```sh
soba settings
soba settings --service SERVICE_ID
soba settings --group GROUP_NAME --json
```

本体が停止している場合は、コマンドの前にグローバルの `--offline` を付けます。別の保存先を選ぶ場合はコマンドの前に `--state-dir PATH` を付け、以降の操作でも同じ保存先を使ってください。

単一ポートの SSH 転送では、共有 Core API がネットワーク、不変の相手 ID、接続先 SSH ポートに基づく `HostKeyAlias` 付きのコマンドを返します。`USER` を SSH ユーザー名に置き換えてください。サーバーのホスト鍵は別の方法でも確認します。この別名では `known_hosts` への新規登録が必要な場合があります。ホスト鍵の検証は有効のままにしてください。

単一ポートの Web 転送では HTTP URL の候補を返します。HTTP/HTTPS の動作確認は行いません。HTTPS では元のホスト名・SNI・オリジンが必要な場合があり、ループバック URL は証明書の名前と一致しないことがあります。証明書の検証を維持してください。UDP や複数ポートの設定に、単一ポート用の HTTP/SSH コマンドは表示しません。

`mappings` は両端を含むローカル・接続先ポートの対応です。範囲は簡潔に保持し、除外ポートも反映します。ローカルポートを指定した転送では、除外後の接続先ポートに連続したローカルポートを割り当てます。`localEndpoint` は単一ポートのときだけ表示します。`remoteEndpoints` はコピーして使える単一ポートの接続先だけを返し、複数ポートでは `remoteHosts` が現在のアドレスを返します。いずれも選択中のネットワークと不変の相手 ID を確認できる場合だけ表示します。オフラインではアドレスを推測せず、保存された相手 ID とポート対応を表示します。

保存した接続先は、対象サービスを明示的に開始してから利用します。待受の準備完了は通信の準備を示し、アプリの動作成功は示しません。表示されたアプリ接続先は SOCKS プロキシのアドレスではありません。

## RustDesk グループを保存する

RustDesk サーバーの既存の公開鍵と、選択するネットワークの不変の相手 ID を用意してください。以下の例はプレースホルダーです。ヘルパーはサーバー鍵の生成や接続先サーバーの設定を行いません。

```sh
soba --offline rustdesk setup --backend tailnet --id-peer ID_PEER --key PUBLIC_KEY
```

4つのポート対応と公開鍵を確認します。同じ設定に `--apply --review REVISION` を追加して再実行してください。`REVISION` にはプレビューが返した値を使います。機械処理用の共通 API 表現は `--json` で取得できます。

既定の設定は次のとおりです。

| 役割 | プロトコル | ローカルの接続先 | 転送先 |
| --- | --- | --- | --- |
| NAT | TCP | `127.0.0.1:32115` | ID サーバー、ポート `21115` |
| ID | TCP | `127.0.0.1:32116` | ID サーバー、ポート `21116` |
| Heartbeat | UDP | `127.0.0.1:32116` | ID サーバー、ポート `21116` |
| Relay | TCP | `127.0.0.1:32117` | リレーサーバー、ポート `21117` |

リレーの相手は、既定では ID サーバーと同じです。別の相手は `--relay-peer RELAY_PEER` で指定します。`--id-port`、`--relay-port`、`--local-id-port`、`--local-relay-port` でポートを変更できます。NAT は両側で ID ポートの1つ前を使います。ID ポートは1025〜65535、リレーポートは1024〜65535です。ローカルリレーの TCP ポートは ID・NAT と別にしてください。ID とリレーが同じ相手の場合、接続先の TCP ポートも区別します。

`--name NAME` で新しいグループ名、`--backend lan` で LAN を選択できます。`--loopback-host ::1` は IPv6 ループバックを使います。有効期間の既定は `until-stopped` です。`--ttl 72h` などで全設定に共通の有限の期間を指定できます。保存によってノード登録、着信許可の作成、プロキシの開始、RustDesk アプリの設定変更は行いません。

保存は一括で行います。入力確認、リビジョン、容量制限、ファイル書込みのエラーで設定が部分的に残ることはありません。既存のサービス数・グループ数・保存容量の上限を適用します。同じ設定の再実行は既存グループを保ち、再起動しません。同名のグループに異なる設定を保存しようとすると拒否します。別名を選ぶか、現在の定義を明示的に確認・編集してください。

## 確認・開始・利用・停止

通常のネットワーク設定で soba を起動して接続した後、保存グループを確認し、別の操作で開始します。

```sh
soba --dry-run group start rustdesk
soba group start rustdesk
soba rustdesk settings --group rustdesk
```

独自の保存先では、すべてのコマンドに同じ `--state-dir PATH` を付けてください。開始時に正確な保存設定、現在の不変の相手 ID、許可、待受の競合を再確認します。本体停止中のプレビューではポートの空き状況を確認できません。接続先サービスと必要な許可はあらかじめ用意します。

RustDesk を手動で変更する前に、既存のサーバー・プロキシ設定を控えてください。ヘルパーの正確な ID サーバー、リレーサーバー、公開鍵をコピーします。プロキシは空欄、UDP は有効にし、`remote-ID/r` で接続してください。参加するすべての端末で同じローカルリレーアドレスとポートを使います。異なる構成の混在は未検証です。

```sh
soba group stop rustdesk
```

soba やグループを停止しても、RustDesk の元のアプリ設定には戻りません。SOCKS CONNECT のみの構成では RustDesk 1.4.9 の被操作端末を OSS サーバー 1.1.16 に登録できません。他の用途は個別の検証が必要です。この転送ヘルパーは SOCKS 認証情報を設定しません。

公開鍵の情報は4つの役割とともに、ローカルのプロファイル書出し・読込みで保持します。役割の対応を壊す個別設定・グループの編集は拒否します。ヘルパーの関連付けを意図して解除する場合はグループを確認し、現在のリビジョン、`rustdesk` のないグループ、`removeRustDesk: true` を `group.save` に指定します。転送設定自体は残ります。プロファイルの読込みでは既存の全体プレビューとリビジョン確認を使います。ヘルパー情報を相手向けのサービス検索に公開することはありません。

## 共有ローカル API

CLI と Web は同じ認証付きローカル Core コマンドを使います。

- `rustdesk.preview`: `{configuration: RustDeskSetup}`。正規化した設定、4つのサービス定義、グループ、確認用リビジョン、アプリ接続設定を返す
- `rustdesk.save`: 同じ設定に `expectedRevision` を付ける。サービスを開始せず一括保存する
- `rustdesk.settings`: `{group: NAME}`。正確な ID・リレー設定と4つの役割の状態を返す
- `client.settings`: 任意の `ids` または `group`。正確な対応、取得可能な現在のアドレス、SSH/HTTP ヒント、日英の注意事項を返す

同じコマンドを保存情報だけのオフライン経路でも利用できます。通信 ID の読込み、認証情報の作成、アプリへの接続確認、ネットワーク許可の追加は行いません。待受の準備が完了していても `application` は `unverified` のままです。
