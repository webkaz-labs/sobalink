# 近くの端末との接続セットアップ

[English](CONNECTION_SETUP.en.md) · [セキュリティ境界](SECURITY.ja.md)

このソース実装は、範囲を明示して許可する短時間の LAN backend セットアップを提供します。近隣探索と QR・接続情報は未検証の手掛かりです。両端で相手を選び、相手の画面の QR またはコピーした全文で計画の fingerprint 全体を照合し、それぞれの端末で承認してからペアリングします。メッセージ・ファイルの信頼、自動保存、サービス公開、任意 port の許可は追加しません。

これはソース開発段階です。決定的テスト、隔離 loopback 検証、配布物の検証、実端末検証は別の確認段階であり、互いの代替にはなりません。この文書は実端末や公開済みバイナリでの合格を主張しません。

## 通常の手順

1. 両方の端末で接続画面を開きます。表示名と現在のネットワーク範囲を選び、短時間の広告と正確な bootstrap 待受端点を許可します。中継 host になる場合は、その役割と別の high port も明示的に許可します。
2. 両方で相手を選びます。multicast 探索が使えない場合は、現在のセットアップ接続情報をコピーまたは QR で交換します。読取りだけでは承認せず、任意の探索も始めません。
3. 接続計画を確認します。双方の identity、選出した host、正確な中継 address と certificate pin、各端末の範囲を表示します。LAN backend はローカルで選んだ prefix の strict allowed-LAN-destinations policy を使い、その範囲への UDP/TCP を許可します。物理 interface の隔離やプロセス全体の通信封じ込めを意味しません。
4. 相手の画面の照合 QR またはコピーした全文が一致することを確認します。手動なら 64 文字の fingerprint 全体を照合します。一部の文字、数桁、色、表示名だけで判断しません。両端でそれぞれ承認します。
5. 相互の認証済み protocol 応答を待ちます。設定済み・ペア済み・接続済みは別の状態です。メッセージやファイルの申出を受ける信頼は別途許可します。

未検証の第三者が示した QR や、同じ未検証ネットワーク経由で単に返された照合値は相手の確認になりません。相手端末の画面、または別途確認済みの経路で交換します。

## 許可とライフサイクル

- セッションは最大 120 秒です。候補には別の短い観測期限があり、両側承認前に変更・失効した候補の古い選択は無効になります。両側承認後は検証済みの正確な transcript だけを元の期限まで固定します。
- 探索広告は選んだ alias、ランダム session ID、protocol/capability、bootstrap 端点だけです。恒久 identity、招待、ファイル名、サービス一覧、OS hostname は広告しません。
- bootstrap はローカルで選択済みの相手 session と正確な source/address 範囲だけを受け付けます。受信だけで相手を選択したり、未選択の端点へ callback したりしません。
- 両端の鍵と session ID、alias、公開 scope、session ごとに無作為生成したローカル許可 revision、役割、端点、正確な pin、計画 revision、期限を全文 transcript に結びます。interface 名・hardware の確認情報はローカルに留めます。
- 画面間の照合前に暗号化 proof が証明するのは、自己申告された選択鍵の保有だけです。表示名の人物を認証しません。全文 SHA-256 の照合を使い、攻撃者の鍵選別に弱い未レビューの短い照合コードを導入しません。
- session 順で固定した coordinator が、認証済みの方向別観測から一度だけ host を選びます。互換性のある既存 host を優先し、同条件なら session 順で決定します。失敗した方向は利用不可または不明のままで、FW・sleep 等の原因を推測しません。
- 重複した承認・通信は同じ計画と招待を使います。相手、範囲、役割、端点、証明書の変更は取消と新規 session・再承認を必要とします。
- 相互の接続確認後は探索広告を停止します。正確な session の最終応答のため、bootstrap 待受だけが元の120秒期限まで残る場合があります。再招待や期限延長はせず、明示取消ではこの待受も終了します。
- 取消・期限切れでは所有する探索と bootstrap を閉じ、未使用招待を取り消します。ペア保存が既に起きた可能性があれば復旧が必要と表示し、rollback を主張しません。終了を確認できない所有 resource は復旧の制限を保持します。
- 承認した LAN 設定とペアは今後の利用に向けて保存します。成功後の backend と選択した host 待受は短時間の setup が終わっても停止まで継続します。停止しても保存済みペアの取消にはなりません。
- 別の端末への接続は明示的に新しく始めます。残っている setup の最終応答待受を閉じ、終了確認後の `nextAction: start_new_setup` を待ちます。以前の接続結果と稼働中 LAN backend は残り、新しい画面・session では範囲、役割、照合を改めて承認します。
- 新規 LAN backend は相互成功までセットアップが所有します。取消で、借用した既存 backend を閉じることはありません。

## 既存接続と再起動

既存の認証済み接続は通常の相手操作から利用できます。使うだけなら新しいセットアップは不要です。実行中の LAN host または relay client は、strict な単一 prefix と既存の正確な中継 anchor が計画に一致する場合だけ借用できます。client は新しい host 役を要求せず、相手が同じ既存 anchor のローカル host を提示する必要があります。外部 relay を使う client 同士から新しい host を作りません。

互換性のない保存済みペア、準備済み経路、未確認の起動・アプリ権限は従来のネットワーク設定で確認します。探索の許可でリセットや再開はしません。別の process-scoped backend、終了未確認の所有者、identity 変更は、新しい通信を始める前に停止・再起動または復旧状態になります。同じ profile を offline で開き直して、新しい session を作成します。古い照合結果・承認を再起動後へ引き継がず、TCP や backend の無停止移行を約束しません。

OS の FW、route、ネットワークセキュリティ、router、特権サービスを変更しません。QR 交換は通信制限を解除しません。許可済みで到達可能な host がない場合は、既存の承認済み接続または詳細設定を使います。

## ローカル command 契約

Web と CLI は同じ Core 契約を使います。

- `setup.scopes {}`: 現在のローカル候補と不透明な `scopeId` を読み取る
- `setup.start`: alias、`scopeId`、bootstrap port、host 役と relay port、明示 consent
- `setup.status`: 公開状態、接続情報 text/QR、計画照合。招待を含めない
- `setup.select`: 現在の候補 ID を一つ選ぶ
- `setup.manual`: 制限付きの正規接続情報 text から同じ確認へ進む
- `setup.approve`: 正確な session ID、計画 revision、全文 fingerprint、ローカルでの明示確認
- `setup.cancel`: 正確な session を停止し、取消と復旧必要を区別する

接続情報は `sobalink-setup-contact-v1:` と正規 base64url JSON、照合情報は `sobalink-setup-verify-v1:` と全文 SHA-256 digest です。どちらもアプリ信頼の許可や再利用可能な capability ではありません。

開始応答が不明な場合の `setup.status {}` は、その process の現在 session を読むだけです。特定の client が作成・占有した証明にはなりません。以前の session ID を拒否し、指定した公開 contact・範囲を確認して古い承認を消し、現在の計画全文を再確認してから承認します。他の認証済みローカル client も同じ Core を操作できます。
