[統合済みPR #13](https://github.com/webkaz-labs/sobalink/pull/13)の基盤には、保存画面修正、起動を伴わないお気に入りとグループ操作、通信を発生させない診断、読取り専用端末カードのAPI／CLI／Web操作、保存済み共有ひな形の再利用、Core／CLI／Webでの明示的な代替ポート確認を含みます。設定済みの中継でも、LAN招待の内容確認を終えてからペアにします。参加端末を中継にする操作にはプライベートアドレスの手動指定と、保存済みホストをそのまま起動する確認を加えました。

過去のmain `7d505315` の時点では、[統合済みPR #17](https://github.com/webkaz-labs/sobalink/pull/17)の上限付きローカル端末カードPNG読取りも含まれていました。読取りはテキスト欄への入力までで、内容確認と適用は別の操作です。[最終ソースのCI](https://github.com/webkaz-labs/sobalink/actions/runs/37585215258)と[正式なmain `721662a1` のCI](https://github.com/webkaz-labs/sobalink/actions/runs/37587774557)は、PNGの8件を含む実Chromiumの121件と、全8ジョブに成功しています。

通常利用はユーザー権限のプロセスで動かし、管理者権限、TUN、OSの経路／FW変更、ルーター設定を前提にしません。LAN外は通常Tailscaleを使います。既存の明示的に有効化する WAN 機能は従来の条件で保持し、公開中継の新規配置と単独常駐プロセスは今回の対象外です。転送の途中バイトからの再開、永続送信待ち、対話型端末画面（TUI）、ネイティブUIも含めません。

### 最初に直すalpha.5の確認済み不足

alpha.5のSaved ServicesのWeb側読取り処理は `tailnet` と `lan`（および旧形式の空欄）だけを受理しますが、Coreと保存編集画面は `direct-lan` と `mixed` も対応しています。どちらかの新方式を含む保存プロフィールでは一覧とグループ確認が読み込めず、同じ読取り処理を使う読込みも拒否されます。統合済みの修正は対応方式の検証だけを揃え、解析処理・実際に描画するグループ画面・読込み確認の回帰テストを追加しています。方式の選択や許可、公開済みalpha.5のタグは変更しません。

## 依存関係と実装順

1. **基準版の回帰修正と表示契約。** 保存方式の読取り処理を直し、10領域の回帰項目と既存エラー／経路情報を整理します。公開後文書の記録時点と別作業のCI効率化を保ちます。
2. **サービスの使いやすさ。** 短い状態／診断と広告から使う導線を改善し、お気に入り／セット、保持したオフライン状態、明示的な代替ポート、再利用できる共有ひな形へ進みます。既存のプロフィール／グループの版、確認→適用、容量方針を再利用します。
3. **ペアリングの簡略化。** 既存認証付き招待の周囲に、版とサイズ制限のある連絡先交換を加えます。QRは表現方法であり、連絡先情報は信頼や許可ではありません。秘密はURL・ログ・シェル引数・通常の書出しに含めません。
4. **接続先の継続性：当初の設計順。** ソケット変更前に、ペア世代、送受信者、増加し続ける連番、正確な接続先／範囲、期限、永続保存した最後の連番、保存失敗時の閉鎖を定義・レビューする順序です。当初のdirect LANにはペア世代の関連付けがありませんでしたが、現在の候補は独自の管理対象PairContextを使い、中継の経路の関連付けを流用してはいません。取消後の再ペアで古い更新を復活させてはいけません。候補には安全な待受の設定し直しと通信世代の終了を実装しており、最終統合版の受入はこの設計順の記録と区別します。
5. **任意のLAN探索と中継選択。** 明示有効化した有限のローカル探索を、認証付きの接続先確認に結び付けます。次に、事前許可した中継資格・接続受付・優先選択／復旧を既存の経路調整処理で評価します。発見した端末の無断信頼、未認証の選挙、遠隔インストールを意味しません。
6. **組合せ受入。** 10領域の組合せ、生成Web、来歴、最終ソースのネイティブ・ブラウザー・配布の必須検証を再確認します。実端末の結果は別に記録します。

## リスクと境界

### 端点追跡に残る製品契約

以下は統合中の接続先追従候補にも適用する設計と受入条件です。既存の準備済み中継の復旧だけでは、固定されたdirect LAN接続先を更新しません。ソース実装と限定したネイティブ観測は、最終ソースの配布受入とは区別します。

- 上限と版のある更新を、現在のペア世代、発行者、宛先、トンネル鍵、正規化した変更前後の接続先、増加し続ける連番、明示した有効期間に結び付けます。端末鍵だけでは取消後の再ペアを区別できません。すでに確認した送信先範囲内だけを受け入れ、新しい範囲には別の確認を必要とします。
- 書き出したデータを返す前に発行連番を保存し、新接続先を有効化する前に認証済みの受信証拠と最後に受け入れた連番を保存します。応答喪失時は状態を確認し、未保存と決め付けません。期限切れ・撤回後も再利用防止の証拠を残し、未知の版やカウンターの後退を拒否します。
- 接続先変更を取消と現在のアプリ許可に対して直列化します。レビュー済みの初期方針では、移動時にdirect LANの全接続を一時中断することを許容し、候補ソースはこの境界で旧世代の終了と新世代の生成を実装しています。影響する旧通信世代を閉じ、処理担当の終了を待ってから新しい世代を準備完了とします。既存TCPは切断される場合があり、すでにOSへ渡ったバイトは取り消せません。要求を再送したり、停止・期限切れ・取消済みサービスを復活させたりしません。元の許可が有効な同一プロセスのローカル入口は可能な範囲で維持します。
- 更新を有効化する前に、移行・再起動・保存結果不明時の復旧を定義します。プロセス内の復旧待ちフラグだけでは、再起動後の永続取消を証明できません。ローカル連番も古いプロフィール全体の復元を検出できません。この限界を明示し、巻戻し耐性を主張せず状態の照合を必要とします。
- IPv4／IPv6、複数NIC、同時更新、片側／両側の移動、中継の休止／喪失、資源上限を確認します。旧接続先も承認済みの連絡経路も届かない場合は、内容確認付きの手動交換を案内します。探索や再試行だけで存在しない通信経路を作ることはできません。

[独立したメタデータパッケージ（オンラインのソース）](https://github.com/webkaz-labs/sobalink/blob/main/internal/endpointmeta/README.md)には、厳密で上限付きの交換形式、固定の試験データ、符号化・復号処理の検証テスト、変更候補と保存結果のデータモデルが入りました。残る製品証拠には、現在のアプリ許可、ライフサイクルの排他的な管理、実プロフィールの移行と永続保存結果、Core／通信処理統合、中断・繰返し操作、同一ソースのネイティブ／ブラウザー受入を含みます。合成データの保存試験は、実通信や異常終了後の復旧保証ではありません。模擬の許可や通信エンジン全交換によるループバック試作だけでは、この契約の成立を確認したことにしません。

### LAN中継の最小運用と実現性

まず、明示選択した到達可能な参加端末をホストにします。広告する正確なプライベートアドレス、ポート、証明書の状態、現在の待受状態を示し、開始前に確認します。保存ホストの起動は、保存したIDと確認済み設定を再利用します。相手から到達できる状態で、ホストを動かしておく必要があります。

双方が互いの着信を受けられなくても、別ホストへ接続できる場合には、そのホストが役立ちます。一方の参加端末でホストでき、他方から届くなら第三端末は不要です。許可された経路がすべて閉じていたり、唯一届くホストが休止していたりすれば、自動選出だけでは接続できません。ルーター変更や遠隔への自動インストールを代替手順にはしません。

任意のローカル探索は有限の手掛かり収集として実現可能ですが、自動探索とホストの自動選出は未実装です。将来の候補はすでに動作し、中継を明示許可し、IDと接続受付の役割を証明して、確認済みの送信先・資源方針を満たす必要があります。その後に既存の準備済み経路復旧による優先選択を再利用できます。発見だけでは許可しません。この実現性整理から、新たな公開中継・単独常駐プロセス・無制限の第三ホスト接続受付の通信方式を今回の範囲へ追加しません。

- **探索は手掛かりです。** 名前・プライベート IP・IP 範囲・マルチキャスト受信は、端末 ID や同じ物理LANの証明ではありません。探索結果だけで送信先範囲を広げたり、別NICを選んだり、VPN境界を越えたりしません。
- **移動後に再会できる経路が必要です。** 両端の移動、AP隔離、UDP／TCP拒否、唯一の中継の休止では、更新経路がなくなる場合があります。適切な手動交換・起動・Tailscale利用を案内し、接続成功を保証しません。
- **中継IDの継続を守ります。** 現在のホスト証明書は固定した証明書情報と IPに結び付きます。IP／証明書変更で承認した証明書を無断交換しません。新候補にはポート到達だけでなく、適切な中継の接続受付 IDも必要です。
- **保存失敗を軽視しません。** 新しい許可は保存確定後に有効化します。縮小や不正な更新は該当通信を止め、永続取消が不確かな状態を復旧後も明示します。鮮度・連番だけで非公開プロフィール全体の巻戻しを解決したことにはしません。
- **利便性と資源上限を分けます。** 連絡先・キャッシュ・探索・到達確認には、設定可能で有限のバイト・候補・同時処理・再試行予算が必要です。論理上の無制限でもメモリー／ソケットの上限と認可を外しません。
- **旧相手と旧状態の扱いを定義します。** 交換形式と非公開状態の移行に版を付け、未知の版は安全側に失敗させます。未対応時は明確な代替手順を示し、無制限に交渉を繰り返しません。

## 必要な証拠

各変更で負例、日英一致、安定JSON、連続クリック／同じ操作を繰り返しても結果が変わらないこと、取消／戻る／閉じる、古い確認の扱いを確認します。フロントエンド変更には型検査・ビルド・デスクトップ／狭い画面での描画確認、Go変更には整形・race・vetが必要です。Linux x64／ARM64・macOS ARM64・Windows x64のネイティブ検査と、既存の署名・来歴検査を維持します。

通信方式の受入には偽装・再利用、取消と再ペア、時計／期限境界、応答喪失、保存中断、同時更新、資源不足、片側／両側の移動、中継休止／喪失、再起動を含めます。アプリ・複数端末／NIC・休止復帰は模擬やループバック試験だけで完了にしません。個別変更の対象テスト成功は、10領域全体やリリースの完了ではありません。
