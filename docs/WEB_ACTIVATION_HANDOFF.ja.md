# Web と CLI での初回有効化

[English](WEB_ACTIVATION_HANDOFF.en.md)

このソース候補は、既存の確認付き直接 LAN 有効化コントローラーに Web からの再起動要求を追加します。ソースの実装は、実機・ブラウザーでの受け入れ完了を意味しません。リリース前にコンパイル、模擬テスト、ブラウザー動作、ネイティブプロセス動作を別途検証する必要があります。

## Web の操作

1. ローカル管理画面で保存済みの相手を選び、正確なエンドポイント、対象範囲、期限を確認します。
2. 確認内容を適用します。新しいプロセスが必要な場合は、一時的な非公開の再起動画面が開きます。その画面でも同じ確認内容であることを確認します。ポップアップがブロックされた場合、補助プロセスは要求しません。
3. 再起動画面を開いたままにします。IPC・Core の正常な終了、プロファイルロックの解放、旧プロセスの実際の終了を確認してから、新しいオフラインの後継を起動します。後継は元の確認内容を再検証し、期限を延長しません。
4. 再起動画面の独立した「開く」ボタンで、この端末の通常のブラウザー起動を要求し、通常のログイン画面に新しい一回用コードを入力します。開けない場合や結果が不明な場合は、表示された認証情報を含まない URL をブラウザーのアドレス欄に貼り付けます。異なるオリジンへ直接移動するリンクは使用しません。旧ブラウザーセッションは移行しません。有効化の進行状況と、別々のネットワーク・待受・アプリの準備状態は新しい画面で確認します。

補助プロセスの有効期限は元の確認期限までです。中止、画面を閉じる操作、一時画面の短い生存確認期限切れ、元の期限切れは、まだ受理されていない処理の続行を止めます。画面を閉じる際の中止要求はベストエフォートで、生存確認の期限切れが補完します。保存済みの確認は取り消しません。ブラウザーによる実行抑制や応答の中断でも続行を停止する場合があります。現在のローカル管理を開き直して状態を確認してから再確認してください。再試行には新しい明示的な確認が必要です。受信結果が不明な非公開コードは再送しません。ポップアップのブロック、続行の辞退・画面閉鎖・期限切れ後は元の画面で再確認できるように戻りますが、自動で再起動を要求することはありません。

## CLI の代替経路

既存の `direct-lan upgrade` の確認・適用・状態確認・中止コマンドも独立して利用できます。適用時は非公開の端末に通常の新しいログインコードを表示します。両経路は同じ正確な確認内容のコントローラーとネイティブ再起動条件を使います。

## セキュリティー境界

- 認証済みのローカル管理セッション、正確なオリジン、CSRF 検証を通った要求だけが引き継ぎを作れます。別の一回用許可を元のセッションと正規化した完全な要求に結び付けます。停止の受理前にログアウト・セッション期限切れ・無効化が起きれば再起動を拒否します。旧本体が停止の受理時に許可を消費した後だけ、同じ期限付き要求が停止応答・実際の終了・検証済みの後継を経て続行します。ピア側のプロトコルから要求したり、別端末を再起動したりはできません。
- 補助プロセスは同じ実行ファイルを内部モードのフラグだけで起動します。初期データは匿名パイプで渡します。権限トークンやログインコードを引数、URL、ログ、ブラウザーストレージ、引き継ぎファイルには保存しません。
- ブラウザーは正確なポップアップウィンドウと数値ループバックのオリジンにだけ一回用トークンを渡します。受け取り時に消費し、別の短命なメモリー内操作トークンを返します。
- 明示的な確認と応答の受領確認が停止要求に先行します。セッションの移行や別のログイン方式は実装しません。
- 通常の新しいログインコードは、認証済みの補助プロセス応答で一度だけ渡します。保持している参照と画面表示は、それぞれ配信、中止、期限切れで消去します。Go やブラウザーによる暗号学的なメモリー消去を保証するものではありません。
- CLI と Web の両方で、変更を行う IPC・進行状況の確認・コード発行は、検証済みのプロセスインスタンスに固定します。中止も元の確認内容全体との一致を必要とし、後から始まった無関係な処理は中止しません。
- 強制終了、ネットワーク試行状態のリセット、自動再確認、永続的な認証情報、アプリへのアクセス許可は追加しません。
