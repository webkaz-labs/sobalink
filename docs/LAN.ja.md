# Tailcat LAN の設定と復旧

[English](LAN.en.md) · [基本手順](GENERIC.ja.md) · [安全性](SECURITY.ja.md) · [確認範囲](VERIFICATION.md#tailcat-の条件)

アダプターと共通処理・CLI に、明示した中継先、相手限定の招待、ペアリング、永続的な解除を実装しました。専用の LAN 設定画面と接続図は統合中です。ローカルの単体・race 試験と静的レビューは通っていますが、stock 実装の2台中継試験は準備済み・未実行です。この手順は実装したコマンドの契約で、実通信の受入完了を示すものではありません。

## 中継先を明示して選ぶ

LAN モードはアカウント認証なしで Tailcat を使います。この本体が正確なプライベート IP・非特権ポートで中継を提供するか、既存の信頼できる中継の数値 IP・ポートと TLS 証明書 SHA-256 ピンを選びます。両側は同じ接続先とピンを使います。公開中継一覧、DNS bootstrap、任意の代替先を自動選択しません。

組込み中継は選んだアドレスだけで待ち受けます。ワイルドカードは使いません。loopback は同じホストでの試験用で、別端末からは到達できません。中継ポートは1024以上とし、管理・探索・ピア・ペアリング・内部入口と競合させません。

バックエンドや中継先を変える前に本体を止めます。保存済みのネットワークを開始せずに管理を開きます。

```sh
soba start --offline
```

そのプロセスを起動したまま、別の端末ウィンドウから操作します。`--offline` は起動時の指定で、後から明示的にネットワークを開始できなくする設定ではありません。

中継を提供する側では、例のアドレスをこの端末に割り当てられたものへ置き換えます。

```sh
soba command network.configure '{"mode":"lan","hostname":"sample-host","lan":{"kind":"host","address":"192.168.50.10:54430"}}'
soba status
```

ホストは非公開の中継識別情報と証明書を作ります。状態には公開の接続先・ピン・ノード公開鍵だけを示します。参加側と信頼できる連絡経路で確認し、非公開の状態ファイルはコピーしません。

参加側は同じ中継を選びます。`RELAY_CERT_SHA256` は、確認した64文字の小文字の証明書ハッシュへ置き換えます。

```sh
soba command network.configure '{"mode":"lan","hostname":"sample-peer","lan":{"kind":"relay","address":"192.168.50.10:54430","certificateSHA256":"RELAY_CERT_SHA256"}}'
```

`kind: relay` 自体は中継を起動しません。待受と入場許可はその運用者が用意します。設定は検証後にバックエンドを開始しますが、待受準備は相手への到達を保証しません。`soba setup --network lan` では保存済みの選択を使えますが、最初の中継先を指定することはできません。

## 意図した識別情報とペアリングする

ネットワークを始める前でも、それぞれの公開識別情報を取得できます。

```sh
soba command lan.identity '{}'
```

未作成なら LAN の識別情報を作って保存し、公開鍵だけを返します。相手の公開鍵を信頼できる連絡経路で照合します。名前は表示用で、本人確認ではありません。

招待側はその正確な公開鍵に、有効期間1〜600秒の一回用招待を発行します。

```sh
soba command lan.invite '{"recipientPublicKey":"RECIPIENT_PUBLIC_KEY","name":"sample-peer","ttlSeconds":300}'
```

結果には `invitation` 文字列、有効期限、相手公開鍵を含みます。招待文字列には秘密の capability があるため、意図した相手にだけ適切な非公開経路で渡します。URL、画像、通常の状態、ログ、シェル履歴、コマンド引数へ含めません。実際の招待を設定例として公開しないでください。

`lan.join` の payload は、完全な招待文字列を `invitation` に入れた JSON オブジェクトです。次は形を示すだけのプレースホルダーです。

```json
{"invitation":"COMPLETE_INVITATION_JSON_STRING"}
```

秘密の payload は非公開の通常ファイルまたはパイプで渡します。秘密そのものをコマンド引数へ置かないための入力方法です。

```sh
soba command lan.join --json-file ./private-join.json
soba command lan.join --stdin < ./private-join.json
```

ファイルには上の外側のオブジェクトを入れます。招待発行の応答全体でも、包んでいない生の招待でもありません。文字列は JSON としてエンコードし、秘密をシェルコマンドに手で連結・エスケープしないでください。入力上限は48 KiBで、対話型端末からの stdin は拒否します。入力ファイルと招待発行の出力を非公開にし、不要になった一時コピーを片付けます。CLI がファイルを読むだけで権限が非公開に変わるわけではありません。

参加成功は `paired: true` と `trusted: false` を返します。秘密状態を保存してから成功を応答し、通信上の対応だけを確立します。受信側は別にアプリの信頼を許可します。

```sh
soba peers
soba trust PEER_ID
```

その後、[基本手順](GENERIC.ja.md)の文字、一括転送、範囲サービスを使います。自動保存はさらに別の希望制で、バックエンド・正確な相手・信頼の世代・保存先に固定します。

## 招待の取消と復旧

招待側は同じ wrapper の形と非公開の入力方法で、自分の未使用招待を取り消せます。

```sh
soba command lan.cancel --json-file ./private-invitation.json
```

| 結果 | 次の操作 |
| --- | --- |
| `lan_cancel_invite_first` | 自分が同じ相手に出した招待を先に取り消してから、相手の招待へ参加する |
| `lan_pair_reply_uncertain` | 無条件に再試行しない。相手で保存済みか確認し、完了したペアを解除してから新しい招待を作る |
| `lan_remote_paired_local_save` | 相手では保存済みだが、この側では未保存。相手側の許可を解除してから再試行する |
| `lan_revoke_not_persisted` | 解除の永続化を確認できず LAN が停止した。非公開状態の保存を修復してから起動する |
| 期限切れ・取消済み・不正な招待 | 意図した相手と中継先を確認し、まだ必要なら新しい招待を発行する |

応答不明は成功でも、両側が変わっていない証拠でもありません。両側を確認する代わりに同じ操作を繰り返さないでください。

## 解除・復旧・停止

アプリの信頼と、通信上のペアリングは別です。

```sh
soba revoke PEER_ID
soba command lan.revoke '{"peerId":"PEER_ID"}'
soba stop
```

最初の操作はアプリの信頼を解除します。`lan.revoke` は通信のペア、アプリの信頼・自動保存、関連するサービスも解除して保存します。関係を完全に終了するときは両側で行います。保存に失敗した場合は永続的な成功を報告せず、LAN を停止します。

保存済みネットワークが起動しない場合は本体を止め、`soba start --offline` で起動します。保存済みの相手は未確認・オフラインとして表示されるので、明示的に解除できます。中継変更には現在の LAN ペアをすべて解除し、バックエンドが停止している必要があります。ローカル中継証明書の期限切れにもこの復旧経路を使い、証明書検査を回避したり古い許可を無言で再利用したりしません。

相手の一時停止は文字・ファイルを遮断し、進行中の送信を取り消します。再開後はファイルを選び直し、取消した送信を自動再開しません。自動保存だけを無効にした場合は一括ごとの承認へ戻ります。どちらも別に許可したサービスを止めないので、必要ならサービス停止またはペア解除を行います。

## 通信範囲と残る制約

相手への直接通信、選んだ中継を通る暗号化ペイロード、その中継先への HTTPS/ICMP 診断を許します。LAN 内だけ・外部通信ゼロの保証ではありません。必須タグでポートマッピング、captive portal 検査、システムプロキシを除き、未対応のプロキシ・上書き環境を拒否します。

組込み中継は sealed HTTPS bootstrap で認証してから、招待された通信ロールを受け入れます。不明な鍵の一律許可はありません。2分の中継接続リースで許可を再確認するため、既存セッションが削除後最大2分、bootstrap の一時許可と重なる場合は初回から約4分まで残ることがあります。アプリの許可と追跡中のアプリ通信は直ちに解除します。

経路は測定できるまで不明です。ペア保存だけでは相手への接触を証明しません。統合中の図はこの端末と観測した相手だけを示し、全員同士の線、帯域、直接・中継経路を作りません。経路変更、スリープ復帰、再接続で既存 TCP を維持する保証はありません。準備中のネイティブ試験は loopback 中継の一つのリース境界の確認で、実 LAN/WAN/NAT の移動や本番の外部通信ゼロを証明するものではありません。
