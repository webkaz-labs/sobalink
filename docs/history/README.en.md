## Maintaining history

- Retain source IDs, run links, failures, scope and then-pending gates. Do not rewrite an old checkpoint as if it described today's product.
- Correct a factual error explicitly; put later implementation and acceptance changes in the current guide, verification record or roadmap.
- Keep Japanese and English records paired. Shared English implementation records are labeled as such in the main index.
- The old top-level parity/plan pages preserve published paths and section anchors. They contain navigation only; edit the full record here.
- When moving another document, update repository links and check the installed documentation layout, including relative links. Do not move a live contract merely because it contains historical evidence.
