# sobalink の使い方

[English](GENERIC.en.md) · [概要](../README.md) · [安全性](../SECURITY.md) · [確認範囲](VERIFICATION.md)

新しい sobalink のローカル開発版と、実行コマンド `soba` の手順です。旧 `tsnet-bridge` 公開版の導入手順ではありません。普段の操作はローカル画面で行い、繰り返す操作や自動処理には CLI を使えます。どちらも Go の共通処理で許可と保存先を検査します。

## 起動して画面を開く

[このチェックアウトをビルド](DISTRIBUTION.md#build-this-checkout)してから実行します。

```sh
soba
```

`soba start` でも同じです。手前で動き続けるので、起動した端末は開いたまま使います。Ctrl+C で稼働中の接続と共有を閉じます。別の端末ウィンドウで次を実行できます。

```sh
soba ui
soba status
```

同じ端末のブラウザーで、表示された正確な `http://127.0.0.1:ポート` を開きます。別に表示される一回用コードを5分以内に入力してください。`soba ui` は URL と新しいコードを JSON で返し、前の未使用コードを置き換えます。コードを URL・ブックマーク・共有ログ・画像へ含めないでください。画面にネットワーク向けの管理アドレスはありません。

起動時のコードは対話型端末にだけ表示します。必要なら `soba ui` を使い、その応答を非公開のログイン情報として扱います。画面のセッションが切れたら新しいコードでログインし直します。通常の状態応答にはコードを含めません。

保存先の既定は OS のユーザー設定ディレクトリ内の `sobalink` です。別の保存先を使う場合は、すべてのコマンドで同じ指定を使います。

```sh
soba --state-dir ./sample-state
soba --state-dir ./sample-state status
```

新しいプロフィールはネットワーク未選択で始まります。画面設定・信頼・サービスの定義は保存しますが、起動し直しても稼働中だった共有の許可や期限、転送進捗を自動再開・更新しません。

## ネットワークを一つ選ぶ

| 選択 | 設定 | 境界 |
| --- | --- | --- |
| 既存 Tailnet | 組込みノードを有効化し、公式の Tailscale 認証へ進む | 選択した Tailnet 内の独立ノード。OS の Tailscale アプリの認証状態を取り込まない |
| Tailcat／明示した信頼できる中継先 | 数値アドレス・ポートと証明書ピンを指定し、特定の相手とペアリング | 統合中。任意の公開中継への代替接続や、外部通信ゼロの保証はない |
| ネットワークなし | ローカルのまま使う | 相手への転送・サービス接続は行わない |

Tailnet では次の順に進みます。

```sh
soba setup --network tailnet --name sample-node
soba login
soba peers
```

返された公式の認証 URL を確認して参加を完了します。認証 URL は秘密として扱ってください。認証キーをコマンド引数で受け取らず、OS の経路や DNS を変更しません。Tailnet のアクセス許可とアプリ自身の認証は別途必要です。

ネットワーク方式は明示して選びます。方式を変えるには本体を停止する必要があり、既存の TCP 接続を Tailnet と Tailcat の間で引き継ぐとは扱いません。Tailcat は最初のスナップショットでは利用できず、設定・ペアリング操作は統合中のため、未検証のペアリングコマンド例はここに載せていません。利用可能な画面と `soba setup --help` を確認し、未対応のエラーが出たら、その経路はまだ準備できていません。

Tailcat が許可する範囲には、相手への直接通信、明示した中継先を通る暗号化済みのペイロード、その中継先への HTTPS/ICMP 診断が含まれます。中継先は自己ホスト、または利用者が明示して信頼したものです。LAN 以外への通信を完全に隔離する機能ではありません。[通信の設計](ARCHITECTURE.md#network-boundaries)

## 意図した相手を信頼する

画面で現在の相手を選び、識別情報を確認してから信頼します。名前は表示用です。同じ名前やアドレスになった別の相手へ、許可を引き継ぎません。

```sh
soba peers
soba trust PEER_ID
```

信頼すると、その正確な識別情報の相手から文字・転送申込みを受け入れます。相手アプリ内部の操作権限を追加する意味ではありません。受信側でも送信者を信頼する必要があり、自分の操作だけで相手側の受信を許可できません。サービスの共有は相手とポートを指定する別の許可です。

信頼を取り消すと、その相手の転送許可と自動保存の世代を無効にし、追跡中の処理と関連する共有を止めます。信頼し直しても、以前の自動保存は復活しません。変更後には稼働中サービスも確認してください。

```sh
soba revoke PEER_ID
```

Tailcat のペアリングでは、明示した招待を通じて鍵の対応を確立します。招待トークンと Tailcat の capability アドレスは秘密です。ペアリング、文字・ファイルの信頼、自動保存、サービス共有は別々の選択です。

## 文字・画像・ファイルを送る

### 文字と画像

文字を入力または貼り付け、内容を確認して送信します。コピーも操作したときだけ行います。クリップボードを裏で読み取ったり同期したりしません。

```sh
soba message PEER_ID "Hello from sample-node"
```

貼り付けた画像は、選択した画像ファイルと同じ一括確認へ入ります。貼り付けただけでは送りません。画像はファイルとして転送し、受信した内容を自動で開いたり実行したりしません。

### 複数ファイル・フォルダー

画面でファイルやフォルダーを選択・ドロップし、相手、相対名、件数、合計容量を確認します。不要な項目を除いてから一括送信します。空フォルダーはブラウザー API で取得できない場合があるため、必要なら CLI を使って結果を確認してください。

```sh
soba send PEER_ID ./image.png ./notes.txt ./sample-folder
```

CLI の相対パスは、コマンドを実行した場所を基準に解決します。リンク、安全でない項目、未対応の項目はたどらずに拒否します。フォルダーは相対パスで転送し、無関係な送信元の絶対パスを相手へ渡しません。

現在の上限は、ディレクトリを含め一括256項目・1 GiBです。メタデータ、階層、未処理申込み、同時ストリーム、予約容量にも上限があります。大きなファイルはバッファー容量を制限して順に送ります。ブラウザーのアップロードは、まずローカル本体への一時保存です。**アップロード100%は相手への到着ではありません。** 相手の承認と、保存済み・完了の状態を確認してください。

### 一括受信を承認する

既定では一括ごとに内容を見て、保存先を選んで承認します。承認するのはその一括のファイルとフォルダーで、送信者への継続的な許可ではありません。

```sh
soba accept TRANSFER_ID /absolute/receive-directory
```

受信側の端末にある適切な絶対パスを使います。Windows では `C:\Downloads\sobalink` などを必要に応じて引用符で囲みます。同名ファイルは別の一意な名前で保存し、既存ファイルを置き換えません。宣言されたサイズと SHA-256 を確認してから確定します。マニフェストにある空フォルダーは保持します。ファイルの権限を制限し、実行属性やリンクは取り込みません。

受信を断るときは画面で辞退し、進行中の処理は取消できます。取消・信頼解除をしても、既に保存したファイルの削除や、送ったデータの回収はしません。

### 相手を限定して自動保存を使う

相手の設定で絶対パスの保存先を選び、自動保存を明示して有効にします。許可は現在の正確な相手、その信頼の世代、その保存先に固定します。同名の相手には適用しません。保存済みの許可は一致する信頼済み識別情報だけに読み込み、有効な間は今後の一括を個別承認なしに保存できます。

相手の操作から自動保存を一時停止・無効化できます。相手の一時停止は転送も止めます。保存先の変更も明示的に行います。信頼解除や識別情報の変更で以前の許可は無効になるため、必要なら確認して有効にし直します。自動保存でも上書き、自動で開く・実行する操作、クリップボード同期は有効になりません。

### 再試行と片付け

```sh
soba retry TRANSFER_ID
soba cancel TRANSFER_ID
soba forget TRANSFER_ID
```

再試行は、両側が同じ一括の状態を保持している間に、未完了のファイルを先頭から送り直します。保存確認済みのファイルは書き直しません。応答だけが失われた場合は、同じファイルの再要求に以前の保存確認を返します。これはファイル単位の再試行で、途中バイトからの再開ではありません。

一括の進捗と保存確認は起動中だけ保持します。どちらかを再起動したら、既に保存したものを確認して、新しい一括として送ってください。新しい一括では別名のコピーができる場合があります。Forget は終了済みの履歴を消す操作で、受信済みのファイルを消しません。

## この端末のサービスを共有する

最初にアプリ自身を起動し、必要な認証を設定します。共有で現在の相手、TCP/UDP、ポートと除外、期限を選び、有効になる範囲を確認して開始します。

```sh
soba share --name preview --network tcp --ports 3000-3003 --peers PEER_ID --ttl 1h
```

選んだ組込みノードのポートを、選んだ相手に提供し、同じ番号の数値 loopback ポートへ対応させます。インターネットの公開 URL を作ったり、アプリを設定したりしません。通常の Tailscale で接続できる相手なら、提供側の組込みノードのアドレスと許可されたポートを使えます。受信側の sobalink は不要です。

- 現在の相手を1〜32件明示します。「全員」の暗黙の許可はありません
- 期限は1秒〜24時間の整数秒で、CLI の既定は1時間です
- TCP の共有範囲はコンパクトに保持し、範囲内の全ポートに OS 待受を作りません
- 許可期間中に範囲内のポートで新しく起動したアプリも対象です。必要な範囲まで狭めてください
- `--ports 3000-3010 --exclude 3005-3007` のように除外できます
- 探索 `54543`、ピア API `54544`、ペアリング `54545` とバックエンド内部の入口はサービス共有へ含めません
- UDP は個別のソケットが必要で、ローカル接続待受と合計64件の上限を共有します。超えたら範囲を狭めます

希望する場合だけ `--discoverable` で、最小限の稼働中サービス情報を許可した相手へ表示できます。CLI では既定で無効です。探索は利用できる許可の情報であり、アプリの動作確認ではありません。画面で探索結果から接続するときは、選んだ共有を再確認して開始します。

ポート競合では操作を失敗させ、別のポートや広い範囲へ無言で切り替えません。同じ番号へ共有する機能と、利用側がローカル入口の番号を変える機能は別です。

## 相手のサービスを使う

画面で利用可能な共有を選ぶか、現在の Tailnet ピアとサービスを手動で指定します。通常の Tailscale 接続先に sobalink は不要です。相手アプリが対象のアドレスとポートで待ち受け、Tailnet とアプリ双方でアクセスを許可している必要があります。

```sh
soba connect --name preview --network tcp --ports 3000 --peer PEER_ID --ttl 1h
```

状態に表示された実際のローカル接続先を、利用するアプリへコピーします。単一ポートの入口は既定で同じ番号です。特権ポートや使用中の番号へ接続する場合は、別のローカル先頭ポートを明示できます。

```sh
soba connect --name ssh --network tcp --ports 22 --local-port 10022 --peer PEER_ID --ttl 1h
```

接続待受は数値 loopback の1024〜65535番を使い、合計64件の上限を消費します。`--local-port` を指定すると、除外後の昇順の相手ポートを、連続するローカル番号へ対応させます。表示された対応を確認してください。共有元の同番号 loopback への対応は変更しません。

待受の準備完了は通信の準備だけです。実アプリで認証し、操作を確認します。TLS 証明書名、SSH ホスト鍵、origin、アプリの認可を維持してください。トンネルだけでは stdio を HTTP に変換せず、遠隔ジョブを実行しません。

## 状態を読む

| 状態・表示 | 意味 |
| --- | --- |
| Saved／保存済み | 定義があるだけで、待受の起動を意味しない |
| Ready／稼働中 | 許可範囲内で通信の準備ができている |
| Direct | バックエンドが直接経路を確認した |
| Relay | バックエンドが暗号化された中継経路を確認した |
| Unknown／不明 | 現在の経路を未確認。遅延から推測しない |
| Reconnecting／再接続中 | 接触が失われた、または作り直している。アプリ側も再接続が必要な場合がある |
| Application unverified | 実アプリの動作は未確認 |

信頼できる経路の観測が得られるまでは不明のままです。同じバックエンド内での direct/relay の変化と、ネットワーク方式の選択変更は別です。経路変更、スリープ復帰、再接続で既存 TCP が残るとは限りません。中断後は現在の相手と許可を確認し、アプリを再接続するか、未完了ファイルを再試行します。

## 停止・信頼取消・更新

```sh
soba status
soba stop-service SERVICE_ID
soba revoke PEER_ID
soba stop
```

状態にある現在の ID を使います。個別停止はそのサービスの接続を閉じます。Stop または Ctrl+C は本体・ネットワーク・稼働中の処理を終了し、非公開の設定と識別情報を残します。期限で許可と追跡中の通信は終了しますが、渡したデータを回収したり遠隔アプリのジョブを取り消したりしません。

sobalink の公開済み更新経路はまだありません。新しい開発ビルドへ替えるときは、プロセスを止め、必要なら状態を非公開の場所にバックアップし、対象ソースから画面と本体を再ビルドします。`soba version` と状態を確認してからサービスを明示して開始します。バックアップには識別情報と相手の情報があるため、公開しないでください。新しい状態ディレクトリでは別途認証と信頼が必要です。旧 `tsnet-bridge` のコマンド・設定との互換性は、新しい製品の要件に含めません。

## 言語・自動処理・困ったとき

共通オプションはコマンドより前に置きます。

```sh
soba --locale ja help
soba --locale en share --help
soba --state-dir ./sample-state status
```

言語は `LC_ALL`、`LC_MESSAGES`、`LANG`、OS の選択の順に確認します。日本語には日本語を、それ以外には英語を使います。画面にも言語・テーマの操作があります。コマンド名、ID、接続先、機械向け JSON は言語で変わりません。CLI は対話式質問ではなく、状態と操作結果を JSON で返します。

詳細操作の `soba command NAME JSON_PAYLOAD` も、同じローカル処理を使います。信頼、セッションや CSRF、ファイルシステムの境界を回避する機能ではありません。[API の契約](../web/API.md)

| 困ったこと | 次の操作 |
| --- | --- |
| ローカルログインが失敗する | 表示された正確な URL を使い、`soba ui` で新しいコードを発行する |
| 相手がいない | 選んだネットワークと認証・ペアリングの状態を確認する |
| 転送が待機する | 受信側で一括承認または自動保存の許可を確認する |
| 一部だけ転送できた | 両側を起動したまま未完了を再試行する。再起動後は新しい一括にする |
| サービスが探索にない | 共有相手と期限を確認する。既知のサービスは手動接続も使える |
| ポート競合・待受上限 | 不要な接続を止め、範囲を狭めるかローカル先頭ポートを明示して変える |
| ソケット操作が許可されない | 必要な待受を許可する実行環境で試す。模擬試験だけでは通信を確認できない |
| 経路不明・再接続中 | 現在の状態を調べてアプリを再接続する。中継や TCP 維持を推測しない |

不具合を報告するときは、コード、識別状態、ペアリング情報、非公開の接続先を除いてください。[受入条件](VERIFICATION.md)ではソースの確認と実機の結果を区別しています。
