# sobalink の使いどころ

[使い方](GENERIC.ja.md) · [English](USE_CASES.en.md) · [安全性](SECURITY.ja.md) · [確認範囲](VERIFICATION.md)

端末同士をつなぎ、相手・ポート・有効期間を決めてアプリのサービスを使えます。文字やファイルも明示して送れます。対象版・同一ソースの自動試験・配布結果は[検証記録](VERIFICATION.md)に示します。実アプリの互換性や実ネットワークの受入は未完了です。[LAN手順](LAN.ja.md)を参照してください。

| 目的 | 操作 | 確認すること |
| --- | --- | --- |
| Web・API を一時的に見せる | 狭い TCP 範囲を相手と期限付きで共有 | 認証、範囲内で後から起動するアプリ、TLS・origin |
| SSH・SFTP・DB を使う | 相手のサービスへローカル入口を作る | SSH ホスト鍵、DB 権限、認証。通常 Tailnet 相手に sobalink は不要 |
| 認証付きの処理 API を使う | 必要なサービスだけ接続する | ジョブ認可・結果・取消はアプリ自身が管理する |
| 短い文字や画像を渡す | 相手を選んで送信。コピーは手動 | 正確な相手、送る内容。クリップボード同期はしない |
| 複数ファイル・フォルダーを渡す | 一括で確認し、受信側が保存先を承認 | 空フォルダー、件数、サイズ、保存完了。一時アップロード完了と区別する |
| 決まった相手の転送を保存する | 相手と保存先を限定して自動保存を有効化 | バックエンド・信頼の世代、一時停止・取消。上書きや自動実行はしない |

## まず一つの小さなサービスで試す

1. 提供側で実際のアプリを起動し、アプリ自身の認証を有効にします。
2. 選んだネットワークを設定します。sobalink の共有では提供側が正確な相手・ポート・有効期間を確認し、通常の Tailnet アプリでは既存のネットワークとアプリのポリシーを使います。
3. 利用側で[案内付きの接続](CLI_GUIDE.ja.md)を使い、表示された実際のローカル入口をアプリに入力します。
4. アプリで操作を試し、使い終わったらサービスを停止します。待受の準備完了だけではアプリの成功としません。

相手がオフラインの間に受け付けたい場合は、[ファイル送信待ち](DURABLE_OUTBOX.ja.md)または[テキスト送信待ち](DURABLE_TEXT.ja.md)を明示的に選びます。ローカル受付は相手の保存記録ではなく、停止しても保存済みの内容は回収できません。

## 二つのアドレス

| 接続先 | 使う側 | 目的 |
| --- | --- | --- |
| 利用側のloopbackとstatusの入口ポート | その端末のアプリ | 選んだ転送へ入る |
| 共有側の組み込みnodeアドレスと許可ポート | 許可された相手 | 共有サービスへ届く |
| 一時的なローカル管理URL | 同じ端末のブラウザー | sobalinkを管理。共有・転送しない |

ポート番号が同じでも別の接続先です。[接続の図](GENERIC.ja.md)と[管理APIの境界](../web/API.md)も確認してください。


通常の Tailscale や既存の共有サービスで目的を満たせる場合、独立ノードや追加のローカル入口が必要かを確認してください。

## 接続とアプリの責任

通信の準備、相手の発見、アプリ成功、遠隔ジョブ完了を分けます。トンネルだけでは証明書やログインを用意せず、stdio を HTTP に変換せず、アプリ設定や遠隔ジョブの割当・取消をしません。停止しても既に送った内容は回収できません。

共有相手は明示して選び、初期値32件を有限値または明示的な無制限へ変更できます。共有の既定は有限の1時間で、24時間を超える期間や明示した解除までを選べます。接続の既定は停止までです。必要なポートと除外を確認します。UDP・ローカル接続・任意のプロキシ待受には、既定64件の調整可能な有限予算があります。[論理設定と資源予算](CAPACITY.ja.md)は別に扱います。TCP を広く共有すると、許可中に後から起動した同範囲のアプリにも到達できるため、便利さと範囲を一緒に確認してください。

Direct・Relay は確認できた経路、再接続は通信を作り直す状態です。現在の経路が不明なら不明のまま扱い、既存 TCP の継続を想定しません。回線変更・スリープ復帰・中断後は、相手と許可を再確認してアプリ接続または未完了ファイルを再試行します。
